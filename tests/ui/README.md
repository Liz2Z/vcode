# UI 需求与预期

## 平台与实现

- 需求：面向 macOS，采用原生方案或 Tauri，不使用 Electron。
- 预期：运行轻量、响应及时；能力实现优先使用成熟第三方包。Git 改动、分支和 worktree 属于统一的 Git 领域，由不同界面入口使用。

## 整体交互与视觉

- 需求：交互参考 VS Code，操作直观，常用操作在合适的位置直接可见。
- 预期：以灰度为主，搭配暖黄色；分隔线克制，内外圆角协调，padding 和 margin 自然；文字渲染清晰，对比足够，模块之间配色连贯。
- 预期：侧栏的玻璃背景与内容统一裁切在外层圆角内，浅色／深色、Files／Changes／Search 切换及宽窄缩放后，四角均无直角底色或背景突出。
- 需求：应用内浮层与弹框默认使用系统原生玻璃材质，并与底层窗口保持清晰的视觉层次。
- 预期：支持的系统采用原生 Liquid Glass，旧系统采用原生模糊材质回退；浮层边缘、背景与投影共同形成可辨认的层次。浅色空白正文、密集代码、diff 增删背景及深色主题下，均能立即辨认浮层边界，文字和操作清晰；打开、滚动底层内容、切换主题及重新打开后仍成立，不遮挡必须保持可见的导航控件。不能仅凭材质控件存在或阴影属性已设置就判定视觉通过。
- 预期：按钮的 hover、按下和选中反馈明显。类型信息与定义跳转通过代码位置交互，不放在顶部按钮排中。
- 预期：可点击的按钮、编辑器标签及关闭按钮、文件／目录整行、可打开的搜索／引用／最近项目结果在悬停时显示手型指针；标签留白也包含在内。禁用按钮、不可用条目、Git 切换列表的当前目标、静态分组标题及列表空白处不显示手型；Recent 当前项仍显示手形，点击保留阅读状态；可折叠的 Changes 分类仍显示手型。
- 预期：滚动、筛选、刷新、标签重排、按钮启用／禁用及浮层关闭后，指针命中范围跟随当前可见区域，不在旧位置残留。源码和输入框保留文本光标，Markdown 链接及可跳转标识符沿用各自规则；分隔条保留左右调整指针。
- 预期：文件树中的文件、文件夹以及 Staged／Unstaged 分类，在未选中、未点击时移入就显示手型；箭头、标题文字和行右侧留白行为一致。不能依赖先点击一次才更新指针，移到列表空白或禁用列表后恢复普通指针。
- 预期：文件树、Markdown、标签、草稿及列表浮层采用纤细的原生小尺寸滚动条；普通源码与 diff 的纵向导航使用 45 点概览条，代码横向滚动仍使用纤细原生滚动条。文件树仍独立预留滚动条位置，不覆盖文件名、Git 状态或分组数量；不修改用户系统滚动条偏好。
- 预期：分支和 worktree 选择器的图标、文字与 hover 背景之间保留清晰、对称的左右内边距；长名称截断时也不贴边。
- 预期：顶部左侧由 worktree 选择器承担主标题，分支选择器紧跟其右；不再单独重复展示项目标题。主标题层级清晰，窄窗口及长名称下自然截断、与右侧操作不重叠；切换 worktree 后标题直接更新。普通文件夹也显示当前目录名且清晰可读，未打开目录时显示 VCode。
- 预期：分支和 worktree 选择按钮只显示当前分支名、worktree 目录名，不添加 Branch／Worktree 文字前缀；通过图标、悬停说明与辅助功能标签区分用途，切换后名称及时更新。普通文件夹的分支入口显示“—”并禁用。
- 预期：分支和 worktree 按钮中的图标完整清晰，图标与文字垂直居中且保留稳定间距，不重叠、不裁切；普通、hover、按下、选中和禁用状态切换时位置保持稳定。窄窗口和长名称只压缩、截断文字，图标不被挤小；点击图标、文字或留白均触发对应按钮。

## 应用图标

- 需求：使用定稿的灰白折纸 V，左侧纸带在上，右侧纸带在下，底部只有一处折叠。
- 预期：未自选图标时，Finder、Dock 与应用关于面板使用对应构建的默认图标；不同尺寸及 Retina 显示下轮廓清楚、透明边距完整，原折纸设计不增加额外三角折面或金色装饰。重新构建后仍保留已收录的图标，不恢复旧的蓝绿 V。
- 需求：View → App Icon 提供 Origami（折纸）、Lightsaber（光剑）、Gummy（软糖）、Spectrum（光谱）、Clock Colorful（多彩钟表）、Clock Bauhaus（包豪斯钟表）六款图标，每项显示对应缩略图，并标记当前选择；没有打开项目时也能使用。
- 预期：两款钟表图标采用用户选定的一体圆角矩形表盘版本，保留七个内圈刻度、11:04 窄 V 指针、反向短尾和小黄色轴心；Clock Colorful 为浅杏色底配紫色／青色指针和彩色刻度，Clock Bauhaus 为暖白底配红蓝指针及黑色刻度，不替换成沿边刻度版本。
- 预期：选择后立即更新运行中应用的 Dock 图标，下次打开 About VCode 显示同一款；所有图标在浅色／深色、不同 Dock 尺寸和 Retina 下完整清晰，保留透明边距。菜单重复打开、连续切换及主题切换后只勾选当前图标，所有缩略图不受应用主图标尺寸变化影响。
- 预期：选择保存到 XDG CONFIG_HOME 的应用配置，退出重开后恢复；缺省时按当前构建默认选择，preview 为光剑、release 为折纸。Use Build Default 清除自选偏好，立即恢复当前构建默认，重开后继续跟随构建默认；更新应用不覆盖已有有效选择。
- 预期：运行时切换不修改安装包及签名，Finder 中的图标保留构建默认；切换不重载文件、改变焦点文档、光标、滚动位置或未保存内容。图标资源不可读、配置损坏或保存失败时明确反馈，不使应用图标变空，不丢失其他配置，也不显示与实际生效图标不符的勾选。
- 需求：图标库控制安装包体积，默认图标仅保留一份完整 ICNS，备选图标使用原有 1024 像素透明 PNG，不做有损压缩、不重复收录默认图标。preview 与 release 均保留六款可选项，缩略图、Dock、关于面板及重启恢复的图像、清晰度与透明边距保持正确。

## 全部文件浏览

- 需求：通过树状目录浏览项目代码，点击文件阅读完整源码。
- 预期：导航入口为 Files，内部标题为 FILES，统一使用 Files 命名；首次打开、刷新及从 Changes／Search 返回后，不出现 Explorer。
- 预期：文件树默认折叠；展开某一层时才加载对应目录节点，文件内容按需读取；打开大项目时不提前展开或创建全部节点。
- 预期：Files 展示被 Git 忽略的文件和目录，包括生成目录与依赖目录；被忽略的普通文件也能直接点击阅读。Git 内部 `.git` 元数据仍不作为源码目录。
- 预期：被 Git 忽略的文件和文件夹名称使用灰色，展开后被忽略目录的后代同样置灰；已跟踪的例外和普通文件保留正常文字颜色。置灰不代表禁用，仍可展开、点击阅读，hover／选中反馈正常；浅色和深色下均能辨认。修改忽略规则后自动刷新更新颜色，切换模式、清空筛选和复用行时不残留旧颜色；搜索排除和按需加载规则保持有效。
- 预期：忽略项使用独立、更淡的灰色，与普通文件名有明显层级差异；不能复用标题、路径等通用次要文字色而导致弱化不足。浅色主题让忽略项更浅，深色主题降低忽略项亮度；普通文件文字、选中底色和其他次要文字保持原有层级。
- 预期：被忽略或无需检索的目录默认折叠，展开时只读取该目录下一层，不递归扫描未展开的后代；空目录可见，目录链接不当作可递归目录。展开／折叠、Files／Changes／Search 往返、刷新及会话恢复后均正常，关闭再展开反映当前磁盘内容。
- 预期：普通目录、被忽略目录及空目录展开后都没有空名称文件或多余空白行；目录自身不作为子项出现。刷新、清空筛选及重开恢复后仍保持一致。
- 预期：Files 浏览范围与匹配／搜索范围独立。侧栏文件筛选、⌘P 文件名／路径匹配及项目全文搜索均排除被 Git 忽略的未跟踪内容和原有依赖／生成目录；即使刚在 Files 打开过，也不进入最近文件匹配结果。已跟踪的 Git 忽略例外按原检索规则保留，修改忽略规则后刷新立即生效。
- 预期：已展开的忽略目录发生新增、删除时自动更新可见列表；正在阅读的忽略文件外部修改后源码自动同步，并保留阅读位置。未展开的依赖／生成目录的深层变化不会触发逐层扫描；计数尚未包含这些内容时用加号说明还有更多文件，不将部分索引冒充完整总数。
- 预期：源码显示完整文件内容，路径和当前文件清楚可辨；普通文件夹也可浏览。
- 预期：目录中有 `.DS_Store`、worktree 的 `.git` 普通文件或符号链接时，其他真实目录及源码仍完整列出；新建、重命名后的未跟踪目录也能展开，符号链接不会导致旁边的目录丢失或递归读取链接目标。
- 预期：Files、Changes、文件匹配和全文搜索不展示 macOS 元数据（如 `.DS_Store`、`._` 资源伴生文件及系统元数据目录）；根目录、嵌套目录和按需展开的忽略目录规则一致，刷新与切换视图后不重新出现，计数和改动提醒只对应可见项。普通隐藏配置文件如 `.env.local`、`.gitignore`、`.vscode` 及正常源码保留；`.swp`／`.swo`／`.swn` 是编辑器交换文件，继续沿用原有展示、检索和 Git 操作规则，不按 macOS 系统文件隐藏。筛除只影响项目展示与检索，不删除文件、不修改 Git 忽略配置；分类及目录的批量暂存／取消暂存仅操作可见改动，不顺带改变隐藏项的索引状态。
- 预期：Files 只展示磁盘上实际存在的项目文件；未暂存删除、已暂存删除、重命名后的旧路径及仅包含已删除文件的目录不残留，文件数量随刷新更新。删除记录仍在 Changes 的对应分类中可读 diff；暂存删除后重新创建的同路径文件仍可在 Files 阅读，未跟踪文件正常展示，忽略文件不混入。
- 预期：文件树标题行只展示标题和数量，不展示 Finder 文件夹按钮。
- 预期：筛选结束后可立即点击任意匹配文件切换源码，包括已经打开的文件；不需要先缩放侧栏或切到 Changes 再返回。清空筛选、刷新、滚动及窄侧栏下也保持点击位置与显示行一致。
- 预期：Files 和 Changes 的文件行、目录行均不显示文件或文件夹图标，直接展示名称，不保留图标占位；目录只保留展开箭头，Git 状态及分组数量仍清晰可见。切换列表及复用行视图时，图标不得重新出现。
- 需求：文件树右键菜单支持复制相对路径和绝对路径，文件与文件夹均适用。
- 预期：Files 和 Changes 中右键具体条目即可选择 Copy Relative Path 或 Copy Absolute Path；以右键指向的条目为准，不要求先左键选中，不打开文件、不改变当前阅读或展开状态。相对路径基于当前项目／worktree 根目录，使用实际文件名与目录分隔；绝对路径包含当前根目录，不加引号，空格和中文原样写入剪贴板。已删除文件的 Changes 记录也可复制路径；切换 worktree 后使用新根目录。分类标题、列表空白及禁用列表不提供文件路径菜单。
- 预期：菜单按复制与定位分组，两个复制路径操作连续排列；Changes 用一条原生分隔线将 Reveal in Files 与复制操作区分。Files 仅保留复制组，不出现多余分隔线；两种视图及文件、文件夹菜单均不再显示 Reveal in Finder，不保留空白菜单项或空分组。
- 需求：Changes 文件树右键菜单提供 Reveal in Files（在 Files 中查看），文件和目录均适用；Files 自身不重复提供这项。
- 预期：从 Staged 或 Unstaged 的任一条目执行后切换到 Files，清除阻挡目标的 Files 筛选，逐层展开父目录并滚动、选中右键指向的目标；不要求先左键选中。此前 Changes 的筛选、展开及滚动状态保留，返回 Changes 时恢复；当前 diff／源码、未保存内容、编辑器焦点组及标签保持，定位动作不额外打开文件或改写磁盘。
- 预期：未跟踪、嵌套目录、中文／空格路径和按需读取的忽略目录内容均定位正确，不对整个依赖目录递归扫描。磁盘上已不存在的删除／移动路径禁用定位但仍可复制路径；删除记录对应的同名文件已重新创建时允许定位实际文件。工作区切换后使用当前根目录，旧菜单不把旧路径定位到新项目；分类标题及空白处不提供该操作。

## 项目文件编辑

- 需求：Files、文件匹配、搜索结果与定义跳转打开的普通 UTF-8 文本默认只读，点击底部 Read Only／Editable 状态文字全局切换编辑权限；diff 两侧继续只读，独立草稿继续可编辑。Markdown 在允许编辑时通过 Source 修改，Preview 反映当前未保存内容。
- 预期：底部沿用锁／笔图标与 Read Only／Editable 状态文字，以无常驻背景和边框的点击入口切换所有普通文件权限，不另外增加开关或标签；Edit → Allow File Editing 同步勾选状态。初次启动及每次重开应用默认只读；阅读会话、未保存内容恢复、刷新及切回标签不能绕过只读权限。开关状态不写入持久化配置，单次运行中切项目／worktree 保留当前选择。
- 预期：开关同步控制当前及之后打开的所有普通文件、已有及新建分栏；当前文档的锁／笔图标及 Read Only／Editable 状态独立反映实际权限。草稿始终可编辑，diff 两侧、二进制、超限、符号链接、读取失败和无正文的状态不因开关开启而可编辑；保存或切换确认期间不能绕过临时锁定。
- 预期：关闭开关立即阻止输入、粘贴、剪切及编辑撤销／重做，但保留未保存内容、标签圆点、光标选区、滚动位置、查询及原有撤销记录；重新开启后可接续编辑和撤销。已有改动在只读模式仍可保存或另存副本，关闭／切项目／退出仍提供保存、放弃、取消；干净的只读文件禁用保存入口。
- 预期：普通文件的状态入口首次悬停立即显示手形，无需先点击；文字、锁／笔图标与按钮内留白一致，Read Only／Editable 往返、标题宽度变化和窗口缩放后命中区域及时更新，静止鼠标下改变可用性也同步更新指针。文字和图标均可点击，并提示作用于所有普通文件；行列信息、计数和错误提示独立显示，不重复或替换可点击的模式文字。草稿／diff、无文档及读取失败状态只展示实际模式，不提供误导性的解锁动作，指针使用箭头；计数、行列及状态栏留白同样使用箭头，移出状态栏后由正文或相邻控件接管指针。可通过 Edit 菜单独立控制全局选择。浅色／深色、窄窗口及长状态下文字清楚，不新增常驻底色，不改变正文布局；确认期间不允许绕过临时锁定。
- 预期：模式入口仅在鼠标悬停于可点击区域时显示与应用其他按钮一致的普通灰色背景，平时透明；不使用玻璃、模糊、阴影、彩色描边或跟随动画。文字与图标作为一组，左右各有 8 点额外留白，背景为 4 点小圆角矩形，不紧贴内容或呈胶囊状；增加的留白同样可点击并显示手形。移到状态栏其他文字、留白或移出后立即隐藏，禁用状态不展示；标题切换和缩放后背景与命中范围一致，不挤动状态文字或正文。浅深色下文字和悬停背景均清楚。
- 预期：中文、emoji、多行输入、复制／粘贴／剪切、原生撤销／重做正常；保留语法高亮、行号、亮黄色符号反馈、类型提示与定义跳转。切文件再返回保留未保存内容、光标、阅读位置和该文件的撤销记录，不将撤销应用到其他文件；diff、二进制、超限文件、符号链接及不可读取的文件不变成空白可编辑文档。
- 预期：Edit → Undo／Redo 与正文聚焦时的 ⌘Z／⌘⇧Z 使用当前文件的撤销记录，正文、未保存圆点和另一栏共享内容同步恢复；输入、撤销、重做和新增编辑后菜单可用性正确更新。切换文件或分栏焦点后只操作当前正文，查询输入框聚焦时只撤销查询文字，diff 的编辑撤销／重做不可用。
- 预期：编辑时标签出现未保存圆点，正文恢复到已保存内容后清除；状态文字和图标同步反映 Editable／Read Only。⌘S 与 File 保存菜单写入当前文件，不弹路径选择；成功后清除未保存标记，更新 Changes 分类、改动提醒、diff 与项目搜索。未保存内容不提前写入仓库；UTF-8 BOM、CRLF／LF、末尾换行和可执行权限在保存时保留。

## 改动文件树与分类

- 需求：有 Git 改动且当前不在 Changes 时，在 Changes 标签上显示暖黄色微光圆点提醒。
- 预期：Files 与 Search 中存在已暂存、未暂存或未跟踪改动时均显示圆点；切到 Changes 立即隐藏，离开 Changes 后只要改动仍在就再次显示，不作为一次性未读状态。没有改动、普通文件夹和切换到干净 worktree／分支后不显示，自动同步和手动刷新后及时更新。
- 预期：圆点有清晰但柔和的暖黄色光晕，不持续闪烁，不增加分隔线，不挤动标签或改变点击范围；最小 220 宽侧栏时 Files、Changes、Search 的完整标题仍清晰，圆点不覆盖文字。点击圆点所在位置也能切到 Changes，当前标签选中反馈与原有快捷键正常。
- 预期：提醒点紧贴 Changes 文字右上角，随着文字位置变化而移动，不固定在整个按钮的右边缘；缩放侧栏后间距保持紧凑，文字与圆点均不被裁切。
- 需求：改动文件按树状目录展示，区分已暂存和未暂存两组，分组标题使用 Staged／Unstaged，省去重复的 Changes；保持现有字体、底色和组间距。
- 预期：进入改动视图时，两组及其子目录默认全部展开；两组中的文件、状态和数量对应各自的改动。
- 预期：同一文件可同时出现在两组中；两部分修改即使互相抵消，也不能从列表中消失。
- 需求：Changes 中已删除的文件用删除线区分，参考 VS Code。
- 预期：已暂存和未暂存的删除记录均使用单条删除线与次要文字色，保留清晰的红色 D；删除线仅覆盖文件名，不穿过目录、分类、状态字母和操作按钮。长名称仍可中间省略，hover／选中及浅深主题下清晰可读，删除行仍可查看 diff、暂存或取消暂存。刷新变为其他状态后移除删除样式；同路径重新创建后，Files 与未删除的比较分类中正常显示，控件复用不残留删除线。
- 预期：刷新后保留用户主动折叠的目录；全部文件视图仍遵循默认折叠、按需加载的规则。
- 预期：分组数量紧跟在 Staged / Unstaged 标题后，间距短且固定，不靠右对齐；零、一位及多位数量都完整显示。分组不显示图标时同时收起图标占位，箭头与标题之间不留大块空白。
- 预期：滚动条独立占位，不覆盖分组数量、文件名或文件状态；滚动条出现／隐藏、反复调整侧栏宽度及分组展开／折叠后仍保持上述布局。

## 暂存与取消暂存

- 需求：Changes 的文件和文件夹行右侧提供操作按钮，参考 VS Code；Unstaged 使用「+」暂存，Staged 使用「−」取消暂存。
- 预期：只有鼠标悬停当前行时才显示该行按钮，移出后隐藏，选中但未悬停的行也隐藏；文件／目录按钮位于名称和 Git 状态标记之间，图标／hover／按下反馈、手形与提示清晰；按钮背景为有上下留白的小正方形。窄侧栏、深层目录、长文件名和浅深主题下不遮挡名称、状态或滚动条，不挤动分组数量。Files 不显示这两个操作按钮。Staged／Unstaged 标题行同样仅在悬停时显示「−／+」，分别取消全部暂存／暂存全部；操作范围是整个对应分类，筛选不缩小其范围，分类为空时按钮禁用。按钮显隐不改变名称、计数或 Git 状态的位置，点击分类按钮不折叠分类。
- 预期：文件行按钮位于 Git 状态标记之前；文件夹没有状态标记，按钮直接靠右，不能保留空状态列造成多余留白。不同层级、展开／折叠、宽窄侧栏和按钮显隐后右侧留白一致。文件按钮只操作对应文件；文件夹按钮批量操作该目录及后代在对应分类中的改动，不影响同名前缀的其他目录。折叠、筛选或尚未创建子节点不会缩小目录操作范围；重命名同时处理原路径和新路径。点击按钮不打开文件、不切换当前标签，也不展开／折叠目录；点击行其他区域仍沿用原有行为。
- 预期：暂存将当前工作区文件内容加入索引；取消暂存只还原索引，工作区文件的内容、删除及重命名保持。支持新增、修改、删除、同一文件同时已暂存和未暂存、特殊字符路径，以及没有首个提交的仓库；linked worktree 操作自身索引，其他 worktree 不受影响。
- 预期：操作在后台执行，期间禁用重复索引操作和分支／worktree 切换，阅读仍可继续。成功后分类、数量、提醒点、状态字母与当前 diff 自动刷新，保留筛选、显式折叠、标签、阅读位置及另一分栏的内容；已经移出该比较分类的文件不在列表残留，也不把原行号上的其他文件误显示为选中。
- 预期：索引锁冲突、权限错误或目标已经失效时明确反馈原因，不把失败显示为成功；失败后恢复按钮可用，保留阅读状态及工作区文件，可以重试。切到其他项目后不展示旧请求的迟到结果，不修改新项目的索引。

## 双栏 diff

- 需求：diff 右边缘有整份文件的改动概览条，Git 增删在轨道右侧紧挨着组成一组，组内红色左列代表删除、绿色右列代表新增，修改同时呈现两种标记；空白占位与左右对齐行使用同一位置比例，不渲染另一份缩小代码。
- 预期：源码与 diff 的概览条宽 45 点，有足够的可见宽度与拖动区域，可视范围滑块在浅色、深色下无需悬停即可辨认；悬停及拖动进一步加强灰色反馈，红绿标记始终清晰。标签栏、文件树等其他原生滚动条不随之加粗。
- 预期：整条概览滚动槽沿用现有主题灰度，以轻微明暗差区分，不绘制分隔线或描边，不形成独立的厚重色块；浅色比正文略深、深色比正文略亮。概览四周各留 6 点正文底色的间距，与编辑器外框分开；版本标签对齐正文右缘，避开概览上方。底色仅覆盖正文高度，不延伸进标题或路径栏。概览使用 10 点圆角，与外层容器的 16 点圆角及内缩间距协调，不做胶囊、不增加阴影或渐变；滑块的最小高度、状态反馈、彩色标记与导航行为保持原有规则。
- 预期：灰色可视范围滑块最小高度为 80 点，长文件不缩成难以抓取的小块；轨道不足 80 点时限制在轨道内；内容已完整显示的短文件或空文件，滑块固定占滚动槽一半高度，停在顶部，点击或拖动不会产生多余滚动。放大的滑块继续能连续拖到首尾，正文同步、当前定位比例和水平阅读位置正确，彩色标记尺寸不随滑块变高。
- 预期：滑块采用 8 点圆角，与概览的 10 点圆角协调；静止底色柔和、对比降低，悬停和拖动时逐级增强灰色反馈，浅深主题下仍能辨认范围。彩色标记保持原有清晰度，不随滑块减淡。
- 预期：各类彩色标记保持固定 4 点宽，包括 Git 删除、Git 新增、亮黄色引用及青蓝色查询；概览条或窗口加宽时不随轨道按比例变粗。红绿两列始终紧挨着，黄色在中央、青蓝色查询在左侧独立列显示，按显示行定位；灰色可视范围保留宽拖动区域，不缩成彩色标记的宽度。
- 预期：概览背景、滑块及标记仅在概览自身边界内绘制，不能覆盖 Modified 标题、右栏源码或相邻编辑器；首次打开、点击、拖动、局部重绘及窗口缩放后，左右正文和标题均保持可见，不能以控件存在或滚动值同步代替可见性检查。
- 预期：滚动到非整行位置时，行号、增删标记和正文沿同一视口上下边界裁剪；Original／Modified 固定标题区域内不出现越界行号、代码或残留背景。允许视口边缘自然显示半行，不吸附整行、不改变行高；滚轮、概览定位和窗口缩放后仍一致。
- 预期：概览条始终显示所有改动及当前可视范围；点击轨道可定位，拖动可视范围可连续滚动到首尾，左右正文同步，水平阅读位置保留。滚轮、触控板、普通滚动或定义／历史定位后，可视范围同步更新。
- 预期：双栏 diff 内不显示左右原生纵向滚动条，仅保留右边缘的改动概览；鼠标在任一栏正文上滚轮或触控板纵向浏览时仍同步滚动。两栏横向滚动继续独立，普通源码也通过右侧概览纵向导航，不重复出现原生纵向滚动条。
- 预期：已暂存、未暂存、新增、删除、短文件及空文件均正确；刷新后标记对应新版本。调整窗口、左右比例或编辑器分栏后标记与可视范围仍正确，各编辑器独立；切回源码后清除 Git 标记并保留源码概览，Markdown 预览或关闭文件后不显示概览。浅色、深色下标记与可视范围清晰，不遮挡正文和水平滚动条。
- 需求：点击改动文件后，左右双栏对照修改前后的完整内容。
- 预期：已暂存比较 HEAD 与暂存区；未暂存比较暂存区与工作区。例如三个版本分别为 1、2、3 时，两组分别显示 1→2 和 2→3。
- 预期：行号、增删行与空白占位正确对齐，修改方向和颜色一致；左右纵向滚动同步，横向可独立滚动；拖动两栏比例后内容仍清晰可读。
- 预期：新增文件左侧为空，删除文件右侧为空；空栏不得残留上一份文件的内容。
- 预期：反复刷新未变化的 diff 时不重复生成相同差异；源码、暂存区、分支或比较分类发生变化后立即显示对应新内容，不复用旧版本。优化后的打开、刷新及切换操作保持响应，期间可以继续点击界面。

## 标签与空状态

- 需求：同一文件的源码、已暂存 diff、未暂存 diff 可以分别阅读和切换。
- 预期：标签清楚区分三种内容；切换、关闭和刷新时，各自的版本与比较基准保持正确，不互相串用。
- 需求：标签超过可见宽度后可横向滚动，访问被挤到两侧的文件。
- 预期：鼠标在标签标题、关闭按钮或标签留白上时，普通滚轮可左右浏览标签；触控板横向滑动及惯性滚动自然，斜向手势不叠加两轴距离。只移动标签栏，不切换文件、不重排标签，也不滚动源码。
- 预期：鼠标停住并滚动标签时，hover 背景跟随当前鼠标下的标签和关闭按钮；滚走、被裁剪或移出指针位置的旧标签立即取消 hover，不会同时残留多个关闭按钮的悬停方块。反向滚回、拖动滚动条、调整宽度或重建标签后同样正确；当前活动标签保留正常选中背景。
- 预期：标签溢出时，下方持续显示可直接拖动的细横向滚动条，无须先滚轮唤出；拖动滑块能连续浏览到首尾，过程中不切换文件、关闭标签、重排标签或滚动源码。轨道独立占位，不覆盖标签文字、关闭按钮或路径；标签全部可见时隐藏轨道并收回高度，每个分栏独立。
- 预期：标签栏两侧不显示滚动按钮，也不预留按钮占位，使用滚轮、触控板或下方滚动条浏览。打开或切换到边缘标签、调整窗口或分栏宽度后，当前标签尽量完整进入视口；关闭标签后滚动位置限制在有效范围，空余区域不残留旧偏移。每个分栏独立滚动。
- 需求：打开的文件标签支持右键关闭所有、关闭其他、关闭右侧和关闭左侧，并支持拖拽调整顺序。
- 预期：四项关闭操作以右键点中的标签为基准，不要求先选中它；左右按当前标签顺序判断，没有可关闭标签的操作禁用。关闭未涉及当前阅读标签时保留内容与位置；关闭当前标签时只切换一次，关闭全部后清空阅读区，过期读取不能恢复已关闭内容。
- 需求：关闭当前标签沿用 VS Code 默认行为，优先回到当前分栏中上一个活跃且仍打开的标签。
- 预期：⌘W、标签关闭按钮和批量关闭使用同一选择规则；按最近激活顺序跳过已关闭标签，不按标签左右位置选择。拖拽排序不改变激活顺序，关闭非当前标签不切换当前内容。返回后恢复目标标签自己保存的光标／选区与纵横滚动位置；不将关闭操作等同于导航后退，也不自动重开已关闭的历史文件。
- 预期：源码、Staged／Unstaged diff 和草稿分别记录激活顺序；每个分栏独立。关闭最后一个标签、空分栏和未保存草稿的保存／放弃／取消仍遵循各自规则，取消关闭不删除标签。
- 预期：拖动标签标题或空白部分可以左右排序，有明确的拖动图像和插入位置；拖到栏边缘可横向滚动，到首尾可插入，取消或移出栏后释放不改变顺序。排序不改变当前阅读文件、比较分类、内容或滚动位置；排序后点击、关闭、再次打开已有文件和左右批量关闭都沿用新顺序。
- 预期：打开文件的标签不展示文件类型图标或图标占位；文件名、Staged／Unstaged 分类文字及关闭按钮保持可读、可操作。
- 预期：标签关闭按钮的 hover 背景为等宽等高的圆角正方形，居中显示，距离标签上下边缘均有留白；切换 hover 不挤动文件名或相邻标签，点击只关闭对应标签。
- 预期：全部标签关闭后，只显示空状态；旧源码、diff、路径和增删计数全部隐藏，不出现重叠，迟到的读取结果也不会重新打开内容。
- 预期：尚未打开项目时，中间显示 Open Folder；项目已经打开但没有文件标签时，中间改为提示从左侧 Files 或 Changes 选择文件，不显示 Open Folder 按钮或打开目录的快捷键提示。打开项目后、关闭最后一个标签后和切换 worktree 后均遵循此规则，顶部打开目录入口保留。

## 编辑器分栏

- 需求：编辑器区域支持左右两组，可以同时阅读两个不同文件，区别于一个文件内部的双栏 diff。
- 预期：标签栏右侧直接展示向右分栏按钮，⌘\ 也可创建分栏；已有文件时将当前文件打开到右组，原组的内容、标签和滚动位置保留，随后可在右组打开另一文件。没有文件的已打开项目也能创建空分栏，尚未打开项目时入口禁用。
- 预期：左右各有独立的标签、当前文件、比较分类、Markdown 模式和滚动位置；点击组内标题、正文、空白或关闭按钮均使其成为活动组。文件树打开、⌘W、定义跳转及标签关闭菜单只作用于对应组，活动组的当前标签有暖黄色提示，另一组保留中性选中状态。
- 预期：两个组的读取可同时完成，快速在两边打开、切换同名文件或不同版本时不互相取消，不把迟到内容显示到另一组。两组均可使用 TypeScript 悬停与 ⌘点击跳转，结果和弹框对应发起的组及文件。
- 预期：组间分隔可拖动调整比例，悬停显示与侧栏一致的提示条；两组最小各保留 220 点。侧栏已经很宽时创建分栏，应调整侧栏给两个组让出空间，窗口缩放后不重叠、不出现负宽度。
- 预期：每组右上角可关闭该组；关闭组或其最后一个标签后，另一组保留原文件、标签和滚动位置，并铺满编辑器区域，不残留分隔条。最后一组关闭所有标签后仍显示已打开项目的空状态。
- 预期：刷新同时更新两组并保留各自位置；同一 worktree 切分支时保留两组及打开的文件并更新内容，切换项目或 worktree 后清空旧阅读内容并恢复单组，旧读取与语言查询不能重新显示。

## 阅读位置前进与后退

- 需求：切换文件、跳转定义后，可回到原文件、光标／选区和滚动位置，再前进到刚才的位置。
- 预期：每组标签栏左侧直接展示后退、前进按钮，支持 ⌃− 后退、⌃⇧− 前进；无可用记录时禁用，hover 和按下反馈清晰。
- 预期：每个分栏独立记录和恢复历史；点选哪一组，快捷键就作用于哪一组。操作一组不改变另一组的当前文件、标签、光标和滚动位置。
- 预期：跨文件定义跳转、同文件不同位置的跳转和普通文件切换均可往返；纵向与横向滚动、选区、源码／暂存／未暂存分类、Markdown 预览模式均能恢复。普通标签切换也恢复该文件上次阅读位置。
- 预期：TypeScript 源码也跟随原文本内容恢复位置；文件上方插入内容或调整窗口后，当前行及其在视口中的偏移保持对应，不因旧行数或旧坐标而跳到其他内容。
- 预期：后退后打开新的文件或新位置会丢弃原前进分支；连续快速切换不把迟到内容写入错误的历史，刷新不会新增历史记录。切换项目或 worktree、关闭分栏后，不访问旧工作区或已关闭组的历史。

## 阅读会话恢复

- 需求：重新打开应用后恢复上次项目、编辑器分栏、标签顺序、阅读位置与文件树展开状态；每个 worktree 独立保存。
- 预期：正常退出或关闭主窗口后重开，进入上次 worktree；指定其他项目启动时优先打开指定项目，并恢复该项目自己的会话。普通文件夹同样支持，不同 worktree 即使属于同一仓库、文件相同也不互相覆盖。
- 预期：恢复单栏／双栏、两栏比例、侧栏宽度、活动编辑器组和各组活动标签；每栏的标签顺序、源码／已暂存／未暂存比较分类保持一致。只有当前文件按需读取，其余标签点击时加载；关闭过的标签、全部关闭后的空状态及关闭过的分栏不会重新出现。
- 预期：各标签独立恢复光标、选区、水平和垂直阅读位置；Markdown 保留源码／预览模式及内容锚点，diff 恢复左右各自水平位置和同步纵向位置。文件内容外部变化后优先跟随原可见内容；恢复布局完成前不以临时空内容覆盖已保存位置。
- 预期：Files 与 Changes 分别保留目录展开／折叠、选中行、筛选内容和列表位置；Changes 的显式折叠保留，新目录仍按原规则默认展开。Files 只展开之前打开的目录，其他目录保持折叠和按需加载。
- 预期：切换项目或 worktree 前保存离开位置，返回时恢复各自会话；同一 worktree 内切分支保持现有阅读会话，不套用其他 worktree 的状态。切换失败不覆盖原会话，旧异步加载不串到新项目。
- 预期：快速打开文件后立即退出、连续切换、恢复途中退出及外部删除文件时，已保存的标签与位置不丢失、不崩溃；失效文件显示明确提示，不混入 Files，也不打开 worktree 外的路径。
- 预期：阅读变化合并保存到 XDG 状态目录；重启后可读，兼容旧版只有项目历史的状态。损坏或不可写状态明确反馈且不覆盖原损坏文件，不新增 UserDefaults 写入。

## 外部文件变化自动同步

- 需求：无需手动刷新，外部修改、原子保存、新增、删除、重命名和切换分支后，文件树、源码、Markdown 与 diff 自动更新。

- 预期：两栏分别更新自己的文件与比较版本；暂存区变化也能更新已暂存／未暂存 diff，linked worktree 的 Git 元数据位于项目外时同样生效。
- 预期：内容变化尽量保留光标、选区、横向位置与屏幕顶部的源码内容；在阅读位置之前插入或删除行时跟随原内容，目标内容消失时安全收敛到有效位置，不跳到文件开头。
- 预期：磁盘文件重命名或移动后，已打开的标签、路径和前进／后退历史跟随新路径；文件树移除旧路径并显示新路径。不能确认重命名关系时不猜测目标。
- 预期：已删除文件从 Files 消失，当前源码显示明确的删除提示，不继续展示旧源码；Changes 仍可查看删除 diff。同路径重新创建后自动恢复阅读并尽量保持位置。
- 预期：同一 worktree 外部或应用内切分支后，保留两组布局、文件和阅读历史，更新分支、目录与内容；新分支缺失的文件展示删除提示。切到其他项目或 worktree 则清空旧上下文。
- 预期：密集保存合并刷新，忽略常见构建／依赖缓存事件，不反复重绘未变化内容；同步期间可继续切文件，旧读取和语言查询不会覆盖新内容。

## TypeScript 与语言服务

- 需求：支持 TypeScript 语法高亮和 TypeScript 项目的 LSP；后续考虑增加 Python。
- 预期：TypeScript 源码和 diff 内容有清晰、准确的语法高亮；hover 悬停代码时展示类型，使用处 ⌘点击跳转定义，定义标识符本身 ⌘点击展示引用列表。
- 预期：界面保持灰度与暖黄色，代码中的关键字、类型、函数、属性、字符串、数字和注释有明显的颜色层次；源码与 diff 两栏采用相同规则，增删行背景上文字仍清晰，字符串和注释内部不被其他规则误染。
- 预期：源码、diff 和类型提示中的代码统一为 12 号等宽字体，优先 Monaco，回退 Menlo；行号与源码、增删背景的行高保持一致。
- 预期：只在标识符上悬停时查询类型；普通悬停不改变标识符的背景、颜色或下划线，类型提示仍可正常阅读。提示中的代码块保留缩进并有语法高亮，文档段落、强调、行内代码和列表正确排版，不直接展示 Markdown 围栏。
- 预期：类型提示随内容调整大小；长行可换行、长类型可滚动，移动到提示内可继续阅读和选择文本。提示靠近窗口四边时自动调整位置，完整留在当前窗口和屏幕内；滚动源码、切换文件、调整窗口或按 Escape 后关闭，迟到的请求不能重新弹出旧提示。
- 预期：鼠标离开原标识符或提示弹框后，等待 2 秒才关闭；在代码空白处继续移动不会反复重置倒计时。等待期间回到原标识符或移入弹框，应取消关闭；鼠标留在弹框内可持续阅读、滚动、选择和复制内容，超过 2 秒也不消失。再次移出弹框后重新等待 2 秒。
- 预期：触发其他类型提示时替换旧提示，打开引用列表或其他操作弹框时关闭旧提示；旧计时器不能关闭新提示，旧异步请求也不能使已离开的提示重新出现。
- 预期：链式访问中的各层成员均按实际指向的标识符跳转；跳转到定义后可以继续对成员、参数类型、返回类型和跨文件符号执行 ⌘点击，不局限于第一次跳转或顶级符号；点号、空白不误触发相邻标识符。
- 预期：成功跳转并滚动到目标定义后，目标标识符以暖黄色闪烁高亮 2 秒，随后完全清除；同文件、跨文件、多层级跳转，以及已打开的标签都适用。只高亮目标位置，不改变源码、语法颜色或光标位置；普通打开文件不触发。
- 预期：连续跳转时立即清除旧目标并为新目标重新计时，旧计时器不能提前清除新提示；切换文件、关闭标签或切换工作区后不残留提示。遵循系统减少动态效果设置时采用静态高亮，仍在 2 秒后清除。
- 预期：源码与 diff 右栏的类型和定义对应当前内容；不增加顶部类型／定义／引用按钮，也不提供 F12 或字号操作。
- 预期：真实 TypeScript 项目打开后语言服务可持续使用；初始化期间的悬停和跳转请求可等待服务就绪，不能永久停留在不可用状态。
- 预期：语言服务异常退出时显示具体原因；后续代码交互可尝试恢复。服务就绪后，旧的不可用提示应消失。
- 需求：TypeScript 语言服务使用随应用打包的原生程序，运行时不依赖 Node 或本机安装的 TypeScript。
- 预期：从 Finder 启动后，真实项目仍支持格式化类型悬停、逐层定义跳转、定义处引用列表及文件内语义高亮；外部修改、切换文件和 worktree 后结果对应当前内容。语言服务以单个原生进程运行，资源统计包含该进程；缺少服务或服务异常退出时有明确反馈。

## 编辑器内查询

- 需求：⌘F 在当前编辑器中查找文本，Edit 菜单及快捷键列表提供同一入口；⌘⇧F 继续打开项目全文搜索。
- 预期：查询框悬浮在当前编辑器组右上角、概览条左侧，留出正常间距，始终不遮挡 minimap 轨道、可视范围或标记；不占满编辑器，不新增占位行或挤动正文。窄分栏内自动收窄，输入与按钮仍完整可用，diff 两栏共用一框。选中单行文字后打开查询时作为初始关键词；输入实时展示命中数量与正文高亮，支持大小写与整词匹配选项、上一项／下一项和首尾循环，无结果时明确显示。查询按文字匹配而非正则表达式，不修改内容，不提供替换操作。
- 预期：查询框在支持的 macOS 上使用系统原生 Liquid Glass，浅深主题下保持清晰可读，正文滚动时呈现系统材质效果；旧版系统使用原生模糊材质回退。细边框与柔和投影区分查询浮层和正文，浅色空白正文上也能看清边界；输入框圆角与项目共享样式一致，不用不透明背景覆盖整块玻璃。
- 预期：diff 查询框位于 Original／Modified 固定标题下方，不遮挡版本标题；普通源码与草稿仍在正文右上角悬浮。Aa、整词、前后导航和关闭按钮首次悬停就显示手形，禁用导航显示普通指针；输入区保留文本光标，清空按钮显示手形。正文与浮层互相移入、按下或松开 ⌘、滚动、切主题和调整宽度后，不被下层源码指针覆盖，不必先点击按钮。
- 预期：⌘G／⌘⇧G、Return／⇧Return 和查询框的前后按钮定位命中，Escape 或关闭按钮收起查询并清除查询高亮，编辑器恢复阅读焦点；查找框正常输入中文、粘贴和全选。查询输入焦点不把快捷键发往侧栏过滤或全局搜索。
- 预期：普通源码、草稿以及 diff 当前聚焦版本可查询；从 Markdown 预览调用时进入 Source 后查询。diff 查询定位后两栏同步滚动，空白占位、中文及 emoji 不引起偏移；保持普通源码与草稿的可编辑状态及 diff 的只读状态。查询保持打开时继续编辑普通源码或草稿会更新命中，不主动改变输入光标或选区。
- 预期：搜索结果采用青蓝色淡底，当前命中采用更强的青蓝色底和细边框；identifier 及相关引用继续使用黄色淡底。同一个词同时命中搜索与引用时仅显示搜索样式，不混合两层底色；鼠标拖选和键盘文本选区优先使用系统原生选区样式，即便与当前命中完全相同也不套用查询导航样式。前后跳转、清空、无结果、关闭后不残留边框或错误选区颜色。
- 预期：全部搜索命中同步显示在 45 点概览最左侧独立的青蓝色列，当前命中用更亮的青蓝色强调；引用仍在中央黄色列，Git 红绿在右侧相邻两列，各列固定 4 点宽。同一行同时存在搜索、引用和 Git 改动时四列均可辨，普通源码及 diff 两个版本均正确；同一显示行合并，屏幕外也可见。关闭查询只清除查询标记，不擦掉独立的符号高亮。
- 预期：切换文件、关闭标签、刷新替换内容或切换工作区后关闭旧查询并清除结果，旧后台结果不能恢复；不同编辑器组互不串用。源码与 diff、浅深主题及宽窄窗口下查询框保持在编辑器组内，不遮挡标签或路径标题；关闭后露出原位置正文，正文视口大小与位置不变。

- 预期：点击其他符号替换正文和概览标记，点击空白同步清除；普通 hover、松开修饰键及滚动不清除点击结果。切换文件、关闭标签、切换工作区、刷新内容后清除旧标记，迟到结果不能复活；两组编辑器的标记互不串用。

- 预期：无论从类型原声明、导入语句还是导入后的用法发起查询，都排除原始类型声明；不能只在声明处发起查询时正确。
- 预期：点击任一引用即可打开对应文件并定位到该处；列表可滚动，键盘可选择并按 Return 跳转，Escape 可关闭。没有引用时明确显示空状态，只有一个引用时也展示列表而不自动跳转；查询失败时显示错误，不将失败伪装成零引用。
- 预期：切换文件、工作区、分栏或比较版本，以及外部更新当前内容后，不展示旧查询的迟到结果；从定义判断到引用查询的两步请求均遵循此约束。当前阅读版本的代码片段与其行号一致，其他文件的预览按需加载，不在打开列表时扫描整个项目。

## Markdown 预览

- 需求：支持 Markdown 预览。
- 预期：预览滚动到中间后切换文件，再后退／前进时恢复原来的可见内容及其在视口中的局部位置；即使光标仍在开头、预览被清空并重新排版，或窗口反复收窄和拉宽，也不跳回开头或被旧文本高度限制。
- 预期：预览包含长段落、中文、emoji、强调、列表及代码块时仍可往返；外部在当前内容上方插入段落后，后退仍跟随原内容，而不是原来的像素位置。渲染尚未完成时发生刷新或快速切换，也不能覆盖已保存的位置或显示过期内容。
- 预期：可以阅读排版后的 Markdown 内容，而不只是原始标记文本；标题、列表、链接和代码块清晰可辨。
- 预期：打开 Markdown 默认显示预览；仅 Markdown 源码标签显示 Source / Preview 切换入口，选择状态与 hover、按下反馈清晰。Source 显示完整原文，切回 Preview 恢复排版；刷新保留所选模式，切换普通源码后不留下这两个入口。
- 预期：嵌套有序／无序列表保持层级，代码块保留缩进并使用与源码一致的字号和语法颜色；长文档可滚动、随窗口宽度换行，文本可选择和复制，链接可辨认。
- 预期：Markdown 改动仍显示双栏 diff，预览不覆盖比较内容；关闭最后一个标签或切换工作区时清空预览，过期渲染不能重新出现。

## 分支与 worktree 切换

- 需求：支持切换分支和 worktree，入口直接可见，当前位置清楚。
- 预期：分栏分别阅读源码与 diff 时，反复切换分支、收窄和拉宽窗口均正常更新；两组位置保留，滚动条出现和布局更新不引发闪退、空白或内容重叠。
- 预期：切换后，标题、根目录、文件树、改动内容与语言服务使用新的工作区；旧内容不串入新工作区。
- 预期：分支已在其他 worktree 中使用时，可直接打开对应 worktree；各 worktree 的本地修改相互独立。
- 预期：兼容的本地修改在分支切换时保留；会覆盖本地修改时拒绝切换并明确反馈原因，不强制切换、不自动 stash；失败后保留原有内容和阅读状态。

## 最近打开的项目与 worktree

- 需求：Recent 在窗口最左侧常驻，纵向展示打开过的项目和 worktree，可拖动右边缘调整宽度，达到阈值时切换展示方式。
- 预期：Recent 栏默认宽 48 点，允许从 48 到 360 点拖动；实际最大宽度受窗口及中间阅读区限制，左文件栏与每个编辑器至少保留 220 点。Recent 栏、文件栏与编辑器分栏可分别调整，不重叠、不产生负宽度；缩放窗口后仍正常。
- 预期：宽度低于 160 点时用 9 点小字号居中显示仓库名，保留原名及大小写，不使用首字母缩写；按连字符、下划线、空格及其他非单词字符分词，按可用宽度在词边界换行，最多两行；换行处的分隔符由换行替代，行内分隔符保留，不把 agent、manage 等完整单词拆到两行，超长单词／名称以省略提示而非第三行显示，不撑高行或溢出；未激活项使用柔和灰色，不呈现接近黑色的强对比，当前项保留暖黄色文字及底色，不可用项进一步弱化。worktree 使用所属仓库名，普通文件夹使用目录名，完整名称及具体 worktree 仍可通过悬停详情区分。达到 160 点时显示项目分组、目录名、分支和路径；反复跨过阈值后，紧凑的两行小字与展开的正常单行字号正确切换，不出现旧布局、重复条目、裁切、空白或点击错位。缩到窄模式时清空并隐藏筛选框，恢复宽模式后可继续筛选。
- 预期：最窄模式悬停通过应用内灰色详情卡片显示完整项目名、目录名、分支、绝对路径及当前／不可用状态；同名项目、名称显示不全的项目和同一项目的不同 worktree 仍可通过完整信息区分，点击始终对应准确路径。卡片使用清晰的名称、暖黄色分支与换行路径排版，保持在当前窗口及屏幕内，不使用系统原生 tooltip；它仅展示信息，鼠标移出对应项目行就立即隐藏，不延迟关闭，也不因移入卡片继续保持。显示前移出应取消待显示卡片，滚动列表、切换记录、调整宽度、切项目或关闭应用后不残留旧卡片。代码类型提示的交互与延迟关闭规则保持独立。
- 预期：紧凑与展开模式中，可用记录（包括当前项目）在首次移入时就显示手形，文字与整行留白一致，不要求先点击或选中；缩放跨阈值、滚动、筛选和启用状态变化后仍正确。从其他项目移到当前项目、再移回其他项目时始终保持手形，点击当前项不重新加载或丢失阅读位置；不可用记录、静态分组标题和空白使用普通指针；展开模式当前／不可用行上的移除按钮仍显示手形并可清理，切换期间禁用操作。
- 预期：当前目录有暖黄色文字及背景提示；有效目录的文字或留白可点击切换，hover／按下／选中状态和手形反馈明确；当前目录及不可用目录不重复打开。宽窄模式均支持列表纵向滚动，不显示水平或垂直滚动条，内容仍可通过滚轮／触控板纵向滚动，列表不遮盖代码。
- 预期：Recent 紧凑激活／悬停背景到窗口左侧的可见边距与编辑器到窗口右侧一致；Recent 到 Files 的可见间距与 Files 到编辑器一致。展开、缩回及窗口缩放后仍对齐，不因列表内缩叠加额外留白，拖动区域和缩放范围保持一致。
- 预期：顶部移除原 Recent 浮层按钮，不再额外弹出历史列表；紧凑 Recent 整条窄栏透明，融入窗口底色，不绘制独立色块或圆角底板；仅当前激活项保留柔和底色和暖黄色文字；激活底色与 hover 共用相同尺寸、内边距和圆角，激活项悬停不叠加第二层或放大背景，展开模式保持灰度／暖黄色体系、合理留白和圆角。点击源码、打开其他浮层或按 Escape 不会移除常驻 Recent 栏；与代码类型提示、搜索、快捷键及 Git 选择器相互操作正常。
- 预期：宽模式项目分组标题随列表正常滚动，不悬浮覆盖首行，往返滚动及缩放后文字不重叠。同一 Git 仓库的主目录和关联 worktree 归为同一项目；不同路径的同名项目不合并，普通文件夹也记录。新目录加入列表前部，已存在的项目／worktree 点击切换、重复打开、分支刷新及重启后保持原有项目和组内顺序，只更新当前项与元数据，不跳到顶部；最多保留 40 个目录。
- 预期：成功打开或恢复的目录立即更新 Recent 栏，分支变化更新名称，但后台刷新不改变访问顺序。切换继续使用目标实际分支，不自动恢复历史分支或修改本地文件，根目录、文件树、源码、diff 和语言服务同步更新，阅读会话按 worktree 保存恢复；切换失败不破坏原内容。
- 需求：Recent 栏仍支持逐条清理和全部清空。
- 预期：展开模式每个条目都提供独立的移除按钮，可清理当前和不可用记录；紧凑模式隐藏所有删除／清空按钮，两行仓库名及整行留白均保持可点击；只移除对应绝对路径，不误打开目录、不删除磁盘文件、不关闭当前项目。宽模式显示 Clear All，紧凑模式不显示顶部清空按钮，也不留顶部按钮占位，仅在展开模式提供 Clear All，筛选状态下也清空全部记录。清空后有空状态并禁用清空按钮，不残留空分组。
- 预期：宽模式筛选可匹配项目、目录、分支和路径，支持上下键及 Return 打开；条目变化后不保留错误的选中索引。Escape 离开筛选，继续阅读时 Recent 栏仍在。
- 预期：清理结果及 Recent 栏宽度保存到 XDG 状态，关闭重开不恢复已清理的其他记录；当前项目的启动恢复和阅读会话保持，恢复或主动打开的当前目录仍按访问逻辑重新记入。窄栏／宽栏的最后选定宽度在重启后恢复；窗口临时收窄不覆盖用户选择的宽度，无项目时也可保存宽度。

## XDG 持久化

- 需求：应用持久化数据遵循 XDG Base Directory 规范。
- 预期：历史记录、上次打开的目录和窗口布局保存到 `$XDG_STATE_HOME/vcode/workspace.json`；未设置或为空时使用 `~/.local/state/vcode/workspace.json`，相对路径无效并回退默认目录。
- 预期：配置、用户数据和可重建缓存分别归入 `XDG_CONFIG_HOME`、`XDG_DATA_HOME`、`XDG_CACHE_HOME`，默认分别为 `~/.config/vcode`、`~/.local/share/vcode`、`~/.cache/vcode`；只在实际写入时创建所需目录。
- 预期：重启后历史和上次目录可恢复，窗口布局留在可见屏幕内；新建应用目录权限为 0700，已有目录权限不被改动，状态文件原子写入，不因中途退出留下半份 JSON。
- 预期：首次运行迁移旧偏好中的历史、上次目录和窗口位置，XDG 中已有的状态优先；迁移保存成功后才清理旧键，失败时保留旧数据并明确反馈；不可读取或损坏的状态文件不被静默覆盖。

## 应用资源占用

- 需求：通过 macOS 顶部 VCode 菜单的 Resource Usage… 查看应用资源占用。
- 预期：打开独立的原生窗口，显示 CPU、内存占用、线程数及各进程明细；统计包含 VCode 主进程和 TypeScript 语言服务等子进程，明确显示统计范围与进程数量。
- 预期：窗口打开时每秒更新，CPU 的 100% 表示占满一个核心，多核心可超过 100%；首次采样及新出现的进程尚无 CPU 对比数据时显示等待状态，不冒充零占用。退出的子进程从列表移除；读取失败明确提示，不能静默当作零占用。
- 预期：重复选择菜单聚焦同一窗口；关闭窗口即停止定时采样，重新打开恢复采样且不显示迟到的旧结果。查看资源不干扰文件阅读、分栏或语言服务；长进程列表可滚动，窄窗口下各列与底部说明不重叠、不裁切。

## 应用自动更新

- 需求：应用自动检测 GitHub 发布的新预览版，并支持在应用内下载、安装和重启；VCode 菜单保留 Check for Updates… 和自动检查开关。
- 预期：默认在启动后及运行期间每小时后台检查；关闭自动检查后不再后台检测，重开应用仍保持关闭，手动检查仍可用。更新偏好只使用用户允许的 Sparkle 内部存储，阅读会话仍使用 XDG。
- 预期：手动检查明确反馈检查中、已是最新版、有新版本或网络失败；检查进行中沿用 Sparkle 标准交互，手动检查入口可用于聚焦当前进度窗口；重复点击不创建重复检查、重复窗口或重复下载。后台无更新或网络失败时不打断阅读。
- 预期：发现新版本时显示当前与目标版本，提供安装与稍后处理；取消／跳过保留当前应用与阅读内容。用户可选择自动下载，默认只自动检测，不在阅读时未经确认强制重启。
- 预期：下载显示进度，完成后可安装并重启至目标版本；重启后恢复原项目、分栏、标签顺序及阅读位置。旧版及相同版本不被当成新更新；无签名、签名不匹配或被篡改的更新被拒绝，原应用仍可使用。
- 预期：浅色、深色与跟随系统主题下更新窗口均可读，按钮和信息不裁切；更新检测不改变当前文档、焦点、滚动位置或工作区。

## 源码开头与水平阅读位置

- 需求：打开和重新打开 JSON 等源码文件时，文件开头不能被行号栏遮挡。
- 预期：单行／多行 JSON 的开头大括号、首个键名与缩进完整显示；反复切换标签、阅读历史前进／后退、自动刷新，以及源码与双栏 diff 往返后仍正常，diff 左右栏均适用。
- 预期：首次打开另一个文件从该文件的开头显示，不继承上一个文件的水平滚动；返回已阅读文件时，保留该文件原有的水平阅读位置，未水平滚动过的文件开头始终位于行号栏右侧。


## 白天与深色主题

- 需求：提供适合白天阅读的灰白主题，保留暖黄色强调和现有深色主题。
- 预期：没有保存过主题选择时默认白天主题；View 菜单直接提供 Light Theme、Dark Theme 和 Follow System Appearance，当前选择有勾选状态。切换立即生效，不需要重启；选择跟随系统时，随 macOS 外观变化切换。
- 预期：白天模式使用柔和灰白底、深色正文、清晰的次要文字和偏橙金的暖黄色强调（#9A5B16），减少黄绿感；文字、提醒点及半透明选中背景使用同一暖色体系。深色模式延续原 #E6C579 配色。窗口标题栏、Recent、Files／Changes／Search、输入框、标签、源码、Markdown、diff、行号、类型提示及其他浮层的颜色一致，没有残留暗色块或刺眼纯白色悬停。

- 预期：打开源码、Markdown、diff 或双编辑器时反复切换主题，不重开文件，不改变标签、分栏比例、选区、光标、滚动位置、文件树或 Git 工作区；切换后的现有代码和浮层立即更新，不必切走再回来。
- 预期：主题选择保存到 XDG CONFIG_HOME 下的应用配置，重开应用后恢复；与各 worktree 的阅读会话和 XDG STATE_HOME 数据分开，不新增 UserDefaults 写入。没有配置时可直接使用，配置损坏或不可写时明确反馈并保留原文件。

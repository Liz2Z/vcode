# 快捷键列表的范围与分组裁剪

## 问题和纠正后的预期

初版固定构建实窗发现：系统注入的菜单项被无差别收录，部分修饰键未展示，出现裸 F／E；原生浮动分组背景越出浮层。按 AGENTS.md 记录失败并暂停修改，用户随后明确要求修复并重新验收，并补充“不用展示系统级的快捷键”。

最新范围是 VCode 功能快捷键和代码／结果列表交互。排除复制／全选、隐藏／退出、最小化／全屏等通用项，以及系统自动加入的窗口管理、表情和替代菜单项。分组使用正常内容中的静态标题，随列表滚动，不生成跨越裁剪边界的系统悬浮标题条。

## 原因和修正

遍历 NSApp.mainMenu 会读到 AppKit 注入的菜单项，不能等同于读取应用自己提供的功能。现在由菜单构建器注册功能项，目录遍历只接受这些对象的原始身份；弱引用避免菜单释放后持有旧项，系统复制出的替代项也不被误收录。通用菜单操作保留原绑定，只在查阅列表中排除，不在列表中展示不支持的系统组合键。

旧标题被标记为原生 group row，触发默认浮动分组绘制，而浮层为保留投影不裁剪全部后代。现在改为内容行中的静态标题，使用 plain 表格、禁用浮动分组，并在内层滚动容器裁剪，保留外层阴影。标题与命令文字使用相同的布局内边距，不靠字符串空格对齐。

## 检查点

- 从实际菜单生成 VCode 功能列表，但不能把所有系统注入项都称为应用快捷键；新功能通过菜单构建器自动注册。
- 测试系统项和原功能项的替代副本均被排除；不可用的 VCode 命令仍可查阅。
- 覆盖全部／筛选列表的分组边界、宽窄往返与原生程序化滚动；静态标题不注册可点击反馈。
- 完成修复、自动化和构建后重新固定版本，实窗只操作和记录，不在验收阶段修改代码。

验证结果后续补录，不能用旧构建的核心交互通过覆盖本次两项显示修复。

范围及分组修正自动化补录：最终 11 项快捷键与架构测试通过，发行构建及独立预览包深层签名检查成功。此后固定版本验收，不修改产品或测试代码。

范围及分组修正版实窗结果：⌘K 后 ⌘S 正常打开并聚焦，未打开项目时也可查阅。完整列表为 18 项应用功能与交互（13 组功能绑定、5 类上下文操作），辅助功能完整清单中无隐藏／退出、复制／全选、最小化／全屏、窗口管理或表情系统项；查询 full 无结果。查询 project 正确展示 Find in Project 及 ⇧⌘F。完整和筛选列表截图均显示标题在内部边界内，无原生悬浮背景或额外分隔线，旧越界问题复验通过。列表外点击关闭、View 菜单打开、Escape 关闭及返回原文件筛选框焦点通过；最后重新打开列表供查阅。物理滚动和窗口拖动仍保留工具限制，未重复尝试，宽窄往返和程序化滚动由自动化覆盖。118 项指纹在固定构建验收前后未变，此后只追加结果，没有在 UI 阶段修改产品或测试代码。旧构建失败记录保留，当前两项修复及用户补充的范围要求已验证；未提交或推送。证据与逐项结果位于 `.build/diagnostics/keyboard-shortcuts-repair/`。

# 批量外部打开的首轮等待不能套用单步预算

## 用户反馈与证据

用户提供原生 TypeScript 提交 55a8df9 的 CI #17 失败截图。读取已登录 GitHub 作业日志后，确认 Run automated tests 执行 213 项测试，2 条失败断言都来自 ExternalOpenTests.testBatchExternalOpenKeepsTabsActiveSplitAndRecoversAfterInvalidPath，而不是两个独立用例，也没有原生 TypeScript 的内存或初始化报错。日志链接：https://github.com/Liz2Z/vcode/actions/runs/40277958508/job/121424667258 。

## 原因与边界

已核实：该用例先提交目录、TS 文件、无效路径和中文 JSON 文件四个请求，首个条件同时等待工作区打开和最终文件源码到达。通用 helper 仅给 12 秒，超时断言并不终止执行，紧接着又比较空标签列表，形成第二条失败。该用例后续错误提示、分栏和恢复断言均未报错，总耗时 18.014 秒，说明 12 秒的批次首轮预算不足以覆盖该 CI 运行。云端没有记录每个队列动作的耗时，具体是哪次 Git / 工作区读取变慢尚未核实；不将其写成已证实的产品请求丢失或语言服务故障。

## 修正措施

只把包含冷 Git 发现、工作区加载与四个串行请求的首轮条件等待改为 30 秒，仍等待实际最后文件的路径和源码，不使用固定 sleep 或无条件重试。其他单步操作保留原 12 秒预算。helper 返回等待结果，首轮失败后输出工作区、当前路径、标签和状态诊断并立即结束，避免对未准备好的状态继续执行依赖断言；原有标签顺序、分栏及恢复断言完整保留。

## 检查点

- 分开统计失败用例数与断言数，不能把 2 failures 直接解释为两个测试失败。
- 等待整个批次与等待一次点击使用不同预算，不整体放宽所有测试超时。
- XCTest 断言失败不会自动终止，后续依赖项必须 guard。
- 先检查当前源码与真实 CI 日志，不因刚替换了语言服务就猜测 OOM。
- CI 测试修复不修改产品 UI 或 tests/ui/README.md，不增加无关 UI 用例。

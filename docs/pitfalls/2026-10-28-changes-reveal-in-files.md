# Changes 定位到 Files 应保持阅读状态与目录边界

## 需求与预期

用户要求文件树右键复制相对／绝对路径，并在 Changes 菜单新增“在 Files 中查看”。定位应以右键目标为准，切换 Files、展开父目录并选中目标，保留当前 diff、源码标签和未保存内容。文件与文件夹均适用。

## 已核实的实现边界

Files 和 Changes 共用一个 FileTree，但各有独立筛选、展开与滚动状态。普通选中回调会打开文件；因此定位不能用文件打开回调替代。Files 的筛选仅涵盖可检索路径，忽略／生成目录内容按需读取；带着 Files 筛选直接定位可能找不到实际存在的目标，不能因此扩大搜索范围或改由 Git 改动列表生成 Files。

## 实施措施

继续复用原有路径复制入口。Changes 增加 Reveal in Files，携带菜单创建时的根目录和路径；执行前验证根目录、模式、列表启用与实际路径可用性，防止旧菜单在切工作区后定位到另一个同名文件。已删除且不在磁盘上的路径禁用定位；磁盘已重新创建的同路径允许定位，不能单凭 Git D 状态禁用。

控制器切换 Files 后，清除阻挡目标的筛选，再用抑制文件打开回调的 select 展开并滚动定位。沿用逐层加载，不递归扫描未展开的其他依赖目录。返回 Changes 恢复原有树状态，编辑器活动文档、比较版本及未保存内容保持。

## 防止再犯的检查点

- 同时核对菜单目标、复制内容和导航目标，不依赖已选行或行号缓存。
- Files 原有筛选、Changes 自身筛选、嵌套与按需目录分别检查；选中可见不等于打开编辑器。
- 复制路径对删除项仍可用；定位要按当前磁盘可见性判断，保留重建同路径的情况。
- 菜单启用状态与动作执行校验均覆盖工作区切换及列表禁用，不能仅设置 isEnabled 后依赖原生自动验证。
- UI 阶段固定构建，只记录结果；最终实窗与用户验证结果见对应验证记录，不预先宣称通过。

## 验证结果

275 项完整自动化检查通过。用户在固定 VCode Reveal Files 预览中，针对复制相对／绝对路径、定位到 Files 并保持编辑器、删除项禁用定位但允许复制三项检查明确回复“正常”；据此记录为用户实测通过，不冒充代理完成了受前台焦点限制的右键操作。完整边界见 `docs/verification/2026-10-28-file-tree-context-menu.md`。

## 用户调整菜单组织

用户随后要求右键菜单分类，并移除在访达中打开的入口。此前直接把复制路径、应用内定位及 Finder 定位放在同一列表，功能没有按用途分组，Finder 入口也不再符合用户的范围选择。新预期为复制与定位两组：Changes 在两项复制路径后用原生分隔线隔开 Reveal in Files；Files 只保留复制组，不添加首尾或空分隔线。文件、目录及删除项均移除 Reveal in Finder，相关回调与控制器绑定一并删除，不能只隐藏标题而保留死入口。

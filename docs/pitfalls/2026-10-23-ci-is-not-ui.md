# CI 打包不属于 UI 测试

## 问题与用户纠正

配置 GitHub Actions 自动打包时，将推送触发、产物格式、架构和打包失败行为写进了 `tests/ui/README.md`。用户明确指出这些不属于 UI 测试，要求移除。

## 原因与正确预期

机械套用“新增功能补充 UI 用例”的约定，没有先判断变更是否涉及界面行为。该约定不能把构建、发布和产物校验变成 UI 测试。UI 文档只记录真实界面交互与可见结果；本次 CI 配置没有新增界面行为。

## 修正与检查点

- 删除本次增加的安装包章节，恢复原有 UI 需求文档。
- CI 的触发方式、构建产物、下载位置和签名状态放在项目 README；工作流及打包脚本承担对应的自动验证。
- 后续先判断变更是否影响 UI，再决定是否修订 UI 用例；不得为满足形式要求添加无关条目。

## 补充：打包产物与 Release 是两个交付步骤

用户发现构建已经成功，但 Releases 页面没有版本。此前工作流只上传 Actions Artifacts，没有创建 Release；不能把这两个交付结果混为一谈。用户明确选择每次推送 main 都发布预览版。

补充独立发布任务：依赖测试和打包成功，下载本次提交的产物并校验 SHA-256 后，用工作流 token 创建带 ZIP、DMG 和校验文件的 Pre-release；其他分支不发布。标签包含运行编号和重跑次数，并明确指向本次提交，不覆盖历史标签或附件。构建任务保持只读权限，仓库写权限只授予发布任务。相关说明更新项目 README，不增加 UI 用例。

验收时分别核对工作流语法、分支条件、成功依赖、产物一致性和实际 Release 结果。未取得云端发布证据前，只能报告配置及本地校验完成，不能宣称 Release 已发布。

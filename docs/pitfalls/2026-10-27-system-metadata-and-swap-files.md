# macOS 元数据与编辑器交换文件必须区分

## 问题与纠正后的预期

用户指出文件树仍显示 .DS_Store，要求不展示 macOS 系统文件，并补充 AGENTS.md.swp 截图。代理最初将两者都纳入隐藏规则；用户随后明确“这个不要处理了”“看起来这个不是mac系统文件”。最终仅排除 macOS 元数据，编辑器交换文件继续按原规则展示、检索及参与 Git 操作；普通隐藏配置和可浏览的 Git 忽略内容继续保留。

## 已核实原因

SourceFileStore 原先只把 .DS_Store 放进搜索排除集合，仍将它加入浏览路径；按需目录读取仅排除 .git。Git 状态路径也直接用于 Changes，因此另一入口仍会暴露这些文件。

范围理解上的原因是把第二张图片直接解释成同类系统文件，没有区分编辑器创建的交换文件与 macOS 元数据。收到纠正后撤回交换文件过滤，并增加可见性与可暂存的回归断言。

## 修正措施

使用共享的纯路径可见性规则，覆盖完整扫描、下一层目录读取、WorkspaceState 的可见改动及批量索引操作。Git 原始状态保留完整，避免把展示规则变成 Git ignore 或删除操作。扫描时只对真实目录调用 skipDescendants，不能因跳过普通元数据文件漏掉其后的源码目录。

## 检查点与验证边界

- 区分 Git 忽略但仍可浏览的文件，与用户明确要求不展示的系统元数据。
- 不能将所有临时文件归为 macOS 系统文件；本次交换文件不处理，禁止重新引入后缀隐藏规则。
- 检查 Files、Changes、搜索候选及按需加载，不能只过滤某个列表。
- 保留 .env.local、.gitignore、.vscode 和正常源码，不采用所有点文件都隐藏的规则。
- 批量 Git 操作与可见范围一致，不能因隐藏条目而让其被悄悄暂存或取消暂存。
- 结果以随后回归与实窗记录为准；本记录写入时尚未完成验证。

## 最终范围验证

撤回交换文件过滤后的最终 58 项工作区读取、Git 服务／索引操作、忽略浏览、文件树及架构测试通过，发行构建通过。新增回归同时检查元数据隐藏、交换文件仍可见可暂存、普通隐藏配置保留、下一层读取一致，以及批量暂存／取消暂存不改变隐藏项索引。

独立 mac-metadata 预览实窗确认：e2e 展开只显示源码、不显示已有 .DS_Store；ignored 按需展开仍显示 readable.ts、不显示 .DS_Store；skills 中 AGENTS.md.swp 与 README.md 保留。Changes 只显示交换文件的未跟踪记录，已跟踪且有修改的 .DS_Store 不进入列表及计数；Quick Open 对 .DS_Store 无匹配，对 AGENTS.md.swp 有匹配且可打开对应内容。普通 .env.local 和 .gitignore 保留。

# 文件导航与全文搜索需区分入口及生命周期

用户新增快速打开与项目全文搜索，并明确全文搜索快捷键为 ⌘⇧F，快速打开使用 ⌘P。两者不能复用为原来的文件树过滤，也不能把目录排除、大小写、整词和正则藏在二级菜单。

预期：快速打开按路径与文件名模糊匹配，优先显示最近打开的可用文件；全文搜索在侧栏按文件分组，点击定位源码行列，Markdown 也必须进入源码以保证行号有效。最近文件沿用 XDG 状态存储，按项目目录隔离；结果不得串入其他 worktree 或编辑器组。

实现使用文件清单与后台文件名索引，全文搜索复用官方固定版本的 ripgrep，随 App 打包并核验下载校验和、架构及运行时依赖。探测发现显式传入文件时 ripgrep 会搜索被 glob 排除的路径，因此目录排除在构建候选文件批次前用原生 fnmatch 处理，不能只给显式文件列表附加 -g。分批限制参数长度，流式读取 JSON，UTF-8 字节列转换为 UTF-16 列；不在主线程读取全项目内容。

搜索输入变化、隐藏及工作区切换会取消后台进程，过期回调按请求令牌丢弃。Quick Open 同样只接受最新查询，初次快速输入共享同一个后台索引。文件删除、重命名和已忽略目录沿用项目文件清单，拒绝符号链接目标及越界路径；结果上限与大文件跳过必须可见，错误不能伪装成零结果。

检查点：实际按 ⌘P 和 ⌘⇧F，键盘／鼠标选择、同名路径与 MRU、四种搜索选项、Unicode 定位、Markdown 源码、分栏、取消及切换工作区。自动化、实窗和需要用户验证分别记录；固定构建 UI 验收中不修改产品和测试代码。

155 项全量自动化通过；最后的侧栏状态及错误摘要调整后，29 项相关复验通过，发行构建和内置 ripgrep 隔离运行验证成功。实窗结果在开始固定构建验收后另行补录。

## 搜索入口应与侧栏内容导航并列

命名补充：用户要求统一为 Files。此前导航称 Files、内部标题称 EXPLORER，同一区域混用名称增加理解成本。内部初始标题和刷新／模式切换标题均改为 FILES，沿用标题大写样式。检查点是首次打开、刷新及从 Changes／Search 返回后名称一致；不能只改初始化文案而遗漏 show 中的赋值。

用户纠正：全局搜索入口应与 Files、Changes 放在一起。此前把它放在顶部工具栏，忽略了三者都在切换同一侧栏内容，入口层级不一致。现在使用 Files / Changes / Search 同一行文字标签，移除顶部重复按钮，保留 ⌘⇧F；搜索条件在视图切换时保留，选中状态互斥。检查最小 220 宽度和宽窄往返的完整标题与点击区域。新布局需重新构建验收，不能复用旧布局截图当作通过。

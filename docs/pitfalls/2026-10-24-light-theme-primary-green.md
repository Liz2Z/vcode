# 浅色主色为松柏绿，文字与底色分别保证清晰度

## 问题与纠正后的预期

用户提供松柏绿色卡，明确要求浅色主题的主色改为 #21A675。此前浅深两种主题均采用暖黄色强调，应以本次浅色配色要求为准；深色仍保留暖黄色。

## 原因

原 Theme.accent 同时用于选中底色、拖动条、光晕、按钮文字及链接。#21A675 在浅色背景上的文字对比约为 3，直接替换同一个常量会让小号文字变淡；只改背景则会残留暖金色文字，导致同一主题颜色不连贯。

## 修正措施

浅色 Theme.accent 精确使用 #21A675，用于强调底色与提示标记；另以同色系 #0D6748 作为小号强调文字颜色，覆盖选中按钮、Recent、文件标签、分类数量、链接、快捷键及详情文字。两种语义色在深色外观下均保留原暖黄色。独立的 Git 状态色、diff 增删语义及代码语法色不随主色改变。对比测试检查文字语义色，背景测试仍检查精确的主色，没有放宽原对比阈值。

## 防止再犯

- 不将色卡主色直接套用到所有小号文字；分开定义底色与文字色。
- 检查所有当前项、按钮、标签、Markdown 链接和提示，不能仅替换某个入口。
- 浅深外观分别解析，保留深色既有配色及阅读状态。
- UI 需求中的旧暖黄色描述要明确受主题影响，不修改用户维护的 PRD。

## 用户纠正：减少绿色铺色

用户反馈上一版“不好看”，并同意中性灰选中背景、只在当前项文字、提醒点和拖动提示上保留松柏绿的方向。上一版只是把旧暖色的所有职责一并换成绿色，半透明绿底叠在偏暖灰色上发灰，同时把链接、元数据、按键等次要信息都变成深绿，造成颜色分布过多且沉闷。此处视觉评价来自用户反馈，色彩叠加方式由代码核实。

收敛为独立的 selection 语义色：浅色使用中性灰，深色仍按原暖黄和透明度绘制；当前项文字继续使用绿色，次要说明、链接和快捷键恢复中性灰。Changes 点和拖动标记保留 #21A675，Git 状态／语法／diff 保持原语义。外观测试仍验证实际选中填色与文字对比，并增加选中色三个 RGB 分量的检查，避免只验红色分量而遗漏绿染。

检查点：不能把“换主色”理解为把所有选中、强调与链接都染同一颜色；先区分当前项、辅助信息和面积较大的底色。该收敛版本的验证待补录，前一版通过不代表用户认可视觉效果。

## 暖黄色微调：减少偏绿

恢复暖黄后，用户指出当前颜色有黄偏绿的感受，明确希望偏红一些。浅色强调色由 #88610D 微调为 #9A5B16，色相从约 41 度向约 31 度的橙金方向移动；沿用原来的透明度、灰底及动态颜色机制，不再扩大改造范围。深色 #E6C579、Git 状态色、语法色、两行仓库名与其他独立修复保持原值。色相可由颜色值计算，具体视觉感受以用户反馈为准。

检查点：只调整当前浅色暖黄的色相，不能把微调理解成再次切换整个主题或引入额外中性色实验；仍检查小号文字在普通与 diff 背景的对比。5 项主题测试通过，包含两种外观下普通／增删背景的文字对比及切换后保留阅读状态；不放宽原 4.5 阈值。独立预览实窗确认浅色导航、Recent 当前项、提醒点和活动标签变为偏橙金的暖色，相关源码指纹在检查前后保持一致。证据在 .build/diagnostics/redder-warm-theme/，本次没有重新执行全量 UI 或受限的真实悬停操作。未提交、未推送。

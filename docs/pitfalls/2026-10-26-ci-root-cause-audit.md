# CI 可靠性要从错误判定与等待边界排查

## 用户纠正与问题

用户要求仔细排查并给出真正方案。此前以“本地 49 项、CI 236 项覆盖不同”作为首要解释不充分：本次失败的 FileTree 布局用例就在本地已通过的集合里，跑全量本身不能解决这个差异。

## 已核实的布局根因

临时 XCTest 探针直接使用现有 FileTree、FileCell 和 137 条改动，在本机重建旧长标题并记录布局；探针运行完已移除，产品代码和正式测试均未更改。日志位于本地 `.build/diagnostics/ci-root-cause-20261026/probe.log`。

| 场景 | 文字外框宽 | alignment rect 宽 | intrinsic 宽 |
| --- | ---: | ---: | ---: |
| 旧 Unstaged Changes，208 点 FileTree | 103.0 | 99.0 | 103.5 |
| 旧 Unstaged Changes，220 点 FileTree | 107.5 | 103.5 | 103.5 |
| 当前 Unstaged，208 点 FileTree | 57.0 | 53.0 | 53.0 |

原用例比较 frame.width 与 intrinsicContentSize.width - 0.5。103.0 >= 103.0 使本地通过，但 alignment rect 实际比文字需要的宽度小 4.5 点；外框里的 4 点内边距掩盖了压缩。失败 CI 同一断言实际为 103.0 < 103.5，仅半点变化就变成红灯。不能将这次概括为无害的浮点噪声。

另一个错误是范围：WorkspaceSplitView.minimumSidebarWidth 明确为 220；FileTreeTests 独立实例的 208 点是更窄的组件压力场景，却套用了“标题完整显示”的产品契约。探针确认旧标题在 220 点下本机未压缩，不把 208 点的结果冒称已复现用户可达宽度中的裁切。

## 异步失败的证据与边界

较早的 IdentifierFeedbackTests 在 90ms 定义探测防抖后只留下约 40ms 调度余量，等待 130ms 后直接访问 answers[0]／answers[1]；断言失败不终止执行，最终可能数组越界。已有修正使用事件 expectation 和安全取值，属于正确方向。

ExternalOpenTests 的失败首轮包含目录打开、工作区读取、多个外部请求解析及最终文件到达，却使用原 12 秒默认预算；CI 首条件超时，整个用例耗时 18.014 秒。当前改为 30 秒首轮预算后云端已通过。本机本次临时探针首批最终 JSON 在约 0.54 秒到达；原 CI 没有各阶段时间，不能把整例的 18 秒当作首批完成时间，也不能断言某条 Git 命令就是历史瓶颈。

对照 CI #20 与同代码本地日志，26 个本地耗时至少 50ms 的匹配用例云端／本地耗时比中位数约 1.62；这说明执行速度确有差异，但不足以独立解释早先批次的 12 秒超时。对照表位于本地 `.build/diagnostics/ci-root-cause-20261026/timing-comparison.json`。

## 排查时提出的具体解决方案

1. 修正布局测试契约：正常布局宽度从产品 minimumSidebarWidth 常量取得；完整显示使用文字 alignment rect 与固有文字宽比较。208 点另作压力场景，只要求数量、动作不重叠及合理省略，不强加不可达产品宽度的完整标题要求。失败输出 frame、alignment、intrinsic、缩放、字体与各附件宽度。
2. 异步测试按实际完成事件推进：正向等待不用固定短暂停顿；前置步骤失败用 guard／XCTUnwrap 立即结束依赖断言。队列顺序、取消与错误恢复采用可控依赖和延迟；真实 Git 路线保留独立集成用例。批量打开需明确区分请求入队、工作区就绪、最终文件读取完成，记录各阶段时间；30 秒只是当前端到端上限，不代替阶段完成信号。
3. 增加共同自动化入口：本地与 CI 共用依赖准备、独立 XDG 目录、完整测试和报告输出。记录系统、Xcode／Swift、SDK、Git、依赖和显示缩放；CI 显式选择支持的 Xcode，依赖锁定已有措施继续保留。不承诺本机与托管机器的时序、字体度量完全相同。
4. 验收标准：支持宽度中长标题真实不裁切；窄组件场景合理退化；故意延迟的异步交付仍能通过，丢失或错误结果明确失败；失败一次即可定位到阶段和尺寸。不得通过删断言、重跑到绿或整体放大所有超时实现。

本轮是排查及方案，未修改产品、正式测试、CI 或 Git 设置，未推送。先前 6366e66 的 CI #21 已成功构建并发布；它修复当前短标题内容，不等于上述测试体系方案已实施。未修改用户的 PRD。

# 忽略项不能复用通用次要文字色

## 问题与纠正后的预期

忽略文件置灰的首版直接使用 Theme.muted。用户展示浅色截图，指出对比太弱，并明确选择“忽略项与普通文件名的区别：忽略项更淡”。需要增强普通项与忽略项之间的层级，不是加深文字或修改选中行背景。

## 原因

已核实忽略项复用标题、路径等次要信息颜色；该颜色仍需维持较强可读性，作为 Git 忽略装饰时弱化不够。此前实窗确认了置灰存在与可读，却没有证明视觉层级满足用户预期。

## 修正措施

新增独立 GitStatus.ignored 动态颜色，首版浅色 #8C8C8C、深色 #777777。用户查看预览后反馈对比还可以再大，明确要求继续调整；修订为浅色 #A0A0A0、深色 #666666，进一步弱化忽略项。只用于 Files 中 Git 确认忽略的名称；普通文件、标题路径、删除文字和选中背景保持现有语义。更新已有颜色回归断言及 UI 需求，不修改 PRD。

## 检查点与验证边界

- 明确区分文字与底色对比、普通与忽略项的层级，以及选中背景，存在歧义时先核实。
- 同屏并排观察普通／忽略项，包含未选中和选中状态、普通文件和目录、浅色与深色。
- “测试确认颜色已应用”与“用户认可视觉层级”分开记录，不能以自动化或截图自称满足审美反馈。
- 实现完成后固定版本再验证；本记录写入时最终实窗复核尚未执行。
- 首版浅色截图已能看到忽略项变淡，但用户没有认可该层级，不能把“截图可见”写成用户验收通过。用户提出第二次配色调整后按明确指令继续实现，不从 UI 验收任务自行推定修复授权。

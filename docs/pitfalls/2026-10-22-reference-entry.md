# 引用能力的范围随最新需求更新

## 需求与预期

用户新增要求：类型定义能够展示被使用的位置列表。此前取消的是不合适的全局工具栏入口，旧用例中也曾明确不提供引用查询；新增需求到来后，必须同步更新这些约定，不能继续沿用旧的禁用范围。

预期：类型提示和标识符右键菜单提供上下文入口，列表展示真实语义引用及代码片段，点击后能定位。保留 ⌘点击跳转定义，不重新加入全局按钮或未被要求的快捷键。

## 实现与检查点

- 复用 LSP 引用查询，排除声明本身，按文件分组并去重，避免文本搜索混入同名但不同作用域的类型。
- 不在每次 hover 时自动扫描引用；只在用户调用入口后查询，并按可见结果加载文件预览。
- 区分零引用、查询失败和预览不可读；预览不可读也不能丢掉真实的引用位置。
- 代码片段与查询时的当前文档版本保持一致；切换文档、关闭标签或切换工作区时不能弹出旧结果。
- 验证列表展示之外，还要实际点击结果并核对跳转位置。

## 从导入类型发起查询也必须排除原声明

实窗验收发现，从导入后的类型用法查询时，列表仍显示原始 interface 声明；从声明处查询的旧测试却通过。底层 TypeScript 服务只按 isDefinition 标记过滤，而导入别名与原声明的标记存在差异。新增真实服务回归先复现：原先应为 3 的使用位置返回了 4 个。

结束该轮 UI 测试后，在语言服务基础设施适配器中补充真实定义解析，并从引用结果排除对应位置；不使用同名文本过滤，也不修改第三方依赖。修复后需同时复验声明处查询、导入用法查询、零引用和遮蔽作用域。

修复后的 91 项全量测试通过，包含上述真实服务回归；独立实窗复验从导入类型用法查询时显示 3 个使用位置、2 个文件，原始 interface 声明已排除，键盘选择并按 Return 能跳到对应使用行。两轮 UI 测试均在结束时核对源码指纹，没有在 UI 测试阶段改代码。

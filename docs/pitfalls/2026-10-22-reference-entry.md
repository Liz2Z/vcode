# 引用能力的范围随最新需求更新

## 需求与预期

用户新增要求：类型定义能够展示被使用的位置列表。此前取消的是不合适的全局工具栏入口，旧用例中也曾明确不提供引用查询；新增需求到来后，必须同步更新这些约定，不能继续沿用旧的禁用范围。

预期：类型提示和标识符右键菜单提供上下文入口，列表展示真实语义引用及代码片段，点击后能定位。保留 ⌘点击跳转定义，不重新加入全局按钮或未被要求的快捷键。

## 实现与检查点

- 复用 LSP 引用查询，排除声明本身，按文件分组并去重，避免文本搜索混入同名但不同作用域的类型。
- 不在每次 hover 时自动扫描引用；只在用户调用入口后查询，并按可见结果加载文件预览。
- 区分零引用、查询失败和预览不可读；预览不可读也不能丢掉真实的引用位置。
- 代码片段与查询时的当前文档版本保持一致；切换文档、关闭标签或切换工作区时不能弹出旧结果。
- 验证列表展示之外，还要实际点击结果并核对跳转位置。

## 从导入类型发起查询也必须排除原声明

实窗验收发现，从导入后的类型用法查询时，列表仍显示原始 interface 声明；从声明处查询的旧测试却通过。底层 TypeScript 服务只按 isDefinition 标记过滤，而导入别名与原声明的标记存在差异。新增真实服务回归先复现：原先应为 3 的使用位置返回了 4 个。

结束该轮 UI 测试后，在语言服务基础设施适配器中补充真实定义解析，并从引用结果排除对应位置；不使用同名文本过滤，也不修改第三方依赖。修复后需同时复验声明处查询、导入用法查询、零引用和遮蔽作用域。

修复后的 91 项全量测试通过，包含上述真实服务回归；独立实窗复验从导入类型用法查询时显示 3 个使用位置、2 个文件，原始 interface 声明已排除，键盘选择并按 Return 能跳到对应使用行。两轮 UI 测试均在结束时核对源码指纹，没有在 UI 测试阶段改代码。


## 2026-10-23：定义处 ⌘点击应直接查看引用

用户指出在定义标识符本身 ⌘点击时只看到自身闪烁，要求直接展示被引用的位置。最新预期覆盖本页早前“保持 ⌘点击始终跳定义”的描述：使用处跳定义，定义本身打开引用列表；零引用明确显示空状态，仅一个引用也留在列表中。

已核实原因：TypeScript 返回当前声明作为定义目标，界面把所有单个 definition 结果直接交给导航，因而重新定位当前文件并触发闪烁。新增真实语言服务及 WorkspaceController 回归在旧实现下复现这一失败。

修正时先查语义定义，再比较目标文件与目标起点是否处于当前点击的完整标识符 UTF-16 范围内；不是比较名称、同一行或鼠标点击的精确列。命中自身定义后复用 references 查询及分组列表，清除已有到达闪烁，不执行自身导航；其他目标继续原定义跳转。定义判断与引用查询两步都检查请求令牌、工作区、编辑器、文件、比较版本及文本内容，丢弃切走或更新后的迟到结果。

16 项相关自动化测试通过，覆盖定义标识符开头／中间／末尾、前置 emoji、跨文件和同文件的使用处、零／单个引用、排除声明及遮蔽作用域、多次跳转后的定义再点击，以及请求后切文件不弹出旧列表。界面按钮入口、引用分组和其他语言服务回归同时通过。

固定构建实窗已验证：TypeScript Ready 后，实际 ⌘点击 Payload 声明直接打开 References · Payload，显示 4 references · 2 files；原声明和其他作用域同名类型未混入。引用行的辅助功能点击报告元素不在屏幕内，改用当前截图坐标点击后，Mac 锁屏阻止了后续观察。因此列表结果点击及“使用处跳定义后再点定义开引用”的完整实窗往返为需要用户验证，不反复尝试受限操作，不把已发出的点击当成通过。零／单个引用及往返路径已有自动化覆盖，此处不冒充实窗验证。

本轮实窗验收只执行和记录；结束时核对 99 项源码／测试／约定／相关文档及构建二进制均未变化，随后仅补录本段。证据和逐项结论位于本地 `.build/diagnostics/definition-references/`。

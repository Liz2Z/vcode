# 标识符概览与正文保持同类反馈

## 问题与纠正后的预期

用户要求概览同步显示当前标识符的定义和相关引用，并明确普通源码、diff 都支持。代理最初提出蓝色，用户纠正为与正文高亮对应的亮黄色；不要自行给同一个符号引入不同颜色含义。

## 原因

已核实：正文已有语义引用背景，概览此前仅接收 Git 行变化。原蓝色方案只是代理设计选择，并非用户指定；与已有黄色反馈不一致。

## 修正措施

复用 CodeTextView 已校验、去重并隔离迟到请求的 occurrenceRanges，将 UTF-16 范围按实际显示文本的行偏移映射到概览；不重新匹配同词，不额外请求语言服务或排版屏幕外字形。引用采用亮黄色中央列，Git 红／绿分别保留两侧独立列。普通只读源码使用相同 30 点概览，不重复显示原生纵向条；草稿仍保留原生滚动条。

## 检查点

- 符号、引用、注释、字符串、同名遮蔽作用域与正文语义高亮一致。
- 中文、emoji 的 UTF-16 偏移和 diff 空白行按显示行映射；同一行多个引用只画一个标记。
- 黄色与红绿处于同一行、滑块覆盖、浅色／深色时仍可区分，不越界覆盖正文。
- 空白点击、切文件、刷新、关闭标签和工作区切换清理两处高亮；迟到请求不能恢复旧标记，分栏各自独立。
- 切换源码／diff 不残留 Git 标记；Markdown 预览、空状态不展示代码概览。

## 用户纠正：标记宽度不能随轨道加宽

用户在轨道改为 60 点后指出黄色提示太大，要求每种高亮模式采用固定宽度，不随 minimap 缩放。已核实旧绘制使用 `(track.width - 6) / 3`，轨道变宽会同步放大红／黄／绿标记；宽命中区域与视觉提示厚度被错误绑定。

改为各类标记固定 4 点，保留红左、黄中、绿右的位置及按文件行映射的高度；60 点轨道和灰色可视范围继续承担易命中的拖动区域。像素回归覆盖不同轨道宽度和浅深主题，确保三种标记保持 4 点，不仅检查中心像素颜色。检查时区分标记厚度、文件行跨度和拖动滑块宽度；最终自动化和固定构建实窗结果待补录。

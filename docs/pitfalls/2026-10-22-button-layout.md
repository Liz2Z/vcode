# 原生按钮的实际尺寸与 hover 留白

## 问题与预期

用户指出文件标签关闭按钮的 hover 缺少上下留白，背景应为正方形；分支和 worktree 选择器缺少左右内边距，文件树标题旁的 Finder 按钮应移除。

预期：关闭按钮的 hover 背景等宽等高、垂直居中，与标签上下边缘保持留白；选择器图标和文字不贴背景边缘；移除用户明确不要的入口。

## 原因

AppKit 的 `NSButton` 存在 `alignmentRectInsets`，约束尺寸不一定等于实际绘制背景的视图尺寸。原实现虽然声明关闭按钮为 24×24，原生布局检查得到的实际尺寸却为 24.5×28。选择器也未显式设置内容内边距。

## 修正

让自绘反馈按钮的布局边界与视图边界一致，关闭按钮实际为 24×24，在 32 pt 高的标签内上下各留 4 pt；分支和 worktree 选择器左右各设置 12 pt 内容内边距；移除文件树标题旁的 Finder 按钮。

## 防止再犯

- 检查实际布局后的视图尺寸和绘制范围，不能只看约束声明。
- 区分内容内边距、控件间距和原生控件的布局偏移。
- 分别核对普通、hover 和按下状态，检查背景形状、留白及是否挤动相邻内容。
- 布局检查、截图和真实交互是不同的验证依据。本次实际关闭操作已验证，hover 高亮截图未稳定捕获，不能宣称实际 hover 验证已通过。
- 用户纠正后的视觉与交互预期同步补充到 `tests/ui/README.md`。

## 自动同步后的顶部刷新入口

自动同步接入后，用户指出顶部 Refresh 的作用不明显，并确认移除按钮、保留 ⌘R。按钮原本确实会重读目录、Git 状态和当前内容，但日常变化已自动覆盖，继续占用顶部空间没有必要。

移除顶部按钮及其事件绑定，让 Open Folder 直接使用右侧统一留白；保留 File 菜单中的 Refresh、⌘R 和原刷新流程。检查宽窄窗口下 Recent、Open Folder 与 worktree 入口的布局，并区分这次入口调整与此前尚未修复的 Markdown 历史滚动问题。

## 选择按钮不重复显示类别前缀

用户明确要求分支和 worktree 选择框去掉 Branch、Worktree 文字前缀。原按钮用类别加当前值展示，图标已能区分类别，重复文字占用了名称空间。

按钮改为直接显示当前分支名和 worktree 目录名，保留图标、悬停说明及独立辅助功能标签；无 Git 分支时显示“—”并禁用。检查短名称、长名称截断、普通文件夹和切换后名称更新，不能只去掉文字却保留原类别文字决定的最小宽度。

## Worktree 选择器承担主标题

用户指出 worktree 和分支选择器可以调换位置，让 worktree 承担主标题并移除原主标题。此前项目名与 worktree 目录名来自同一个目录，却在顶部重复显示，层级没有明确区分。

改为左侧 worktree 选择器、右侧分支选择器，移除单独标题视图及绑定；worktree 使用主标题字号与字重，保留图标和完整路径说明，为长名称提供更多空间，分支保持次级字号。普通文件夹和切换忙碌时主标题虽不可点击，仍保持可读对比，避免禁用按钮的默认淡化使唯一标题不清晰。

检查点：长／短名称、窄／宽窗口、初始空状态、普通文件夹、切换后的名称与弹层锚点；不保留一个仅用于测试等待的隐藏旧标题，测试直接观察真实选择器。具体自动化与实窗结果另行记录，不能在验收过程中继续修改代码。

主标题调整验证：25 项相关自动化测试通过，包括窄／宽窗口的顺序、无重复标题、字号层级和普通目录禁用时的可读性。固定构建中实际点击主标题打开并切换 worktree，再通过右侧选择器切到长名称分支；两处名称正确更新，窄窗口长名称与右侧操作未重叠。94 份固定文件指纹在验收前后不变。本次仅验收顶部标题调整，不清除此前用户暂缓修复的 Markdown 重排漂移记录，也未提交或推送。

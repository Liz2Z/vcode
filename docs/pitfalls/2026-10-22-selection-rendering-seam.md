# 多行选区中的竖向绘制缺口

## 问题与预期

用户截图指出连续多行选区中间有一条竖缝。实窗重新选中对应的连续文本后，观察到同一竖列的选区背景与字符同时缺失。

预期：连续选区在每行应覆盖的区域内完整绘制，不遮住字符；调整宽度、滚动或改变选区后，不留下竖向缺口。不能只给缺口补背景而忽略文字缺失。

## 已核实与未核实项

该状态出现在单栏源码中。离屏布局诊断发现 CodePane 的文本容器宽度固定为 10,000,000，跨行选区的原生矩形也接近这个宽度，远超实际视口与文档宽度。离屏整块重绘未复现相同缺口，因此超大容器与屏幕局部重绘是排查方向，尚不能认定为已确认根因。

本轮仅做诊断，未修改产品或测试代码。用户随后切换了正在阅读的文件，停止对该窗口的选区操作，避免覆盖新的阅读状态。

## 用户要求继续修复

用户明确指出不能停在复现与报告，应继续修复。将该要求作为本次修复授权，在实现阶段修改代码与回归测试；完成实现后再固定版本做 UI 验证，不在 UI 验证时继续修改实现。

第一版候选让 CodePane 自己管理实际文档尺寸，28 项相关自动化测试通过，但固定构建的实窗对照仍在同一位置显示竖缝，横向滚动条也被截断。该轮记录为失败，撤销这一组容器和相关测试改动，没有把自动化通过写成修复通过。

## 分隔条的生命周期

对照进一步显示：竖缝宽 8，恰在阅读区正中央，和 ReadingSplitView 的双栏分隔条一致。原实现只隐藏左栏，并动态把 dividerThickness 从 8 改为 0；NSSplitView 的旧分隔视图仍覆盖在已铺满的右栏上。问题与选区颜色或文本字重无关，超大文本容器也不是已确认原因。

修正为单栏时实际移除左栏，双栏时重新插入左栏；分隔条厚度保持稳定，单栏明确隐藏分隔条并跳过分隔绘制。回归覆盖首次打开源码、diff→源码往返、窗口反复变宽变窄，检查单栏实际只有一个排列子视图，双栏恢复两个视图和 8 点间距。

本次用户已明确要求继续修复，因此第一轮失败记录完成后继续实现，而不是从纯 UI 验收任务推定修复授权。下一轮仍固定独立构建，验收过程中不修改实现。

## 检查点

- 同时检查背景和字符，不把视觉缺口理解为正常分隔或只处理背景颜色。
- 覆盖长行、连续多行选区、滚动、窗口宽度变化和局部重绘；离屏截图正确不代表实窗一定正确。
- 修复前通过对照验证根因，不将超大容器这个可疑实现直接写成已确认原因。
- UI 验证发现问题后只记录、报告，不在验证过程中修改产品或测试代码。

## 修复后的验证结果

独立应用使用相同 fixture、窗口和连续多行选区进行前后对照：旧版在阅读区中央出现 8 点缺口，修复版文字与选区背景完整连续。实际打开双栏 diff 并拖动分隔条，辅助功能值从 906 变为 806；返回源码后仅保留外层侧栏分隔条。实际调整窗口尺寸后重新选区，未出现竖缝。验证期间 Sources 与 tests 文件的 SHA-256 与固定版本完全一致，没有修改实现或测试代码。

相关自动化首轮执行 30 项，其中 29 项通过，跳转闪烁定时清理用例出现两条时序断言失败；该组独立重跑 3 项通过。另一次较宽范围重跑在已有 Cmd-hover 用例中遇到回调计数失败并越界终止，未把这轮记录为全绿，也未修改与本次分隔条修复无关的实现或用例。修复前后截图、日志及逐项记录保存在本地 `.build/diagnostics/selection-seam/`，不将“构建成功”替代实窗结果。

最终聚焦于视图呈现、类型弹框和文字布局的自动化回归共 20 项全部通过，包含新增的单栏／双栏切换与窗口尺寸变化用例，以及真实工作区文件树和 Git diff 流程。此结果与上述较宽范围失败分别记录。

# 侧栏在反复调整宽度后的自适应

## 问题与预期

用户指出侧栏自适应偶发异常，尤其在重新调整宽度后；截图中 Changes 标题被截断，多层目录的长文件名在右侧直接裁切。

预期：最小侧栏宽度下固定导航标题完整可见；目录展开、滚动条变化、反复收窄和拉宽后，文件名在当前可用区域省略，图标、状态及数量不被挤出。

## 原因与修正措施

已核实代码中导航按钮留白挤占最小宽度的文字空间；文件树未禁止 NSOutlineView 在展开时自动增加目录列宽，文件名也未降低水平压缩优先级。截图中偶发时序未单独复现，不能据此宣称所有触发路径均已定位。

收紧固定导航按钮内部留白，保留图文间距；禁止展开目录自动增宽列，使用原生宽度自动调整让文档及列跟随视口；文件名占用图标与状态之间的明确区域，并优先压缩文件名。

## 检查点

- 回归覆盖宽→窄→展开多层目录→宽→窄，以及传统滚动条占用宽度的情况。
- 检查真实列宽、文件名单行区域和导航标题完整性，不能仅检查侧栏外框。
- UI 测试开始后不再修改产品或测试代码；失败只记录并报告。不能完成的实窗操作标记为需要用户验证。

## 本次验证与剩余问题

27 项相关自动化测试通过。独立测试窗口实际拖动侧栏 240→208→316→208→316，检查了长文件名省略、拉宽恢复、目录折叠展开、滚动、Files / Changes 切换及窗口宽度变化；UI 测试前后的源码与测试指纹一致。

实窗发现分组计数的对齐仍不一致：已暂存组的 0 有时靠近标题，未暂存组的数量则靠右。此项只记录，未在 UI 测试期间继续修改产品或测试代码。完整复现原始偶发时序尚未完成；系统传统滚动条占宽只通过自动化布局测试覆盖，未改动用户系统设置。

## 用户补充：滚动条遮挡与分组间距

用户随后截图指出滚动条遮挡三位分组数量、箭头与分组标题间距过大，并明确纠正：分组数量应贴近标题，而非统一靠右。

原实现隐藏图标但保留了宽度和间距约束；数量与普通文件状态共用右侧布局，标签的伸缩又使数量位置不一致。原生浮动滚动条还会覆盖行末内容；上次回归只强制测试了传统滚动条，遗漏了真实使用的覆盖模式。

分组改为收起图标占位，数量与标题保持固定短间距；普通文件状态仍保留在行末。此文件列表使用独立占位的原生滚动条，避免覆盖任何行内容，不修改系统滚动条偏好。

检查点：区分分组数量与文件状态的排版含义，覆盖 0、9、137、多层目录、滚动条显隐及宽窄反复变化；UI 测试前固定版本，发现问题只记录，不边测边改。

补充修复的验证：12 项相关自动化测试通过；独立实窗检查了 0／137、刷新后的 9／137、分组折叠与展开、滚动条显隐，以及 240→208→316→208 的实际侧栏拖动。数量均紧跟标题且完整可见，隐藏图标未留下原来的空位；源码与测试指纹在 UI 测试前后保持一致。本轮未发现新的相关问题。

# 首次提交也必须补齐 UI 验收缺口

## 需求与预期

用户选择先不推送初始提交，补齐 UI 验收。仓库初始化和自动化通过不能替代尚未实现的 Markdown 预览，也不能将模拟事件测试写成真实窗口验收通过。

## 原因与修正

Markdown 需求此前只记录在测试文档中，应用仍以源码展示。补充基于 Foundation Markdown 解析和 AppKit 文本视图的预览，只在 Markdown 文档中提供 Source / Preview，保留现有双栏 diff 和文件生命周期。

⌘悬停的旧验证没有稳定捕获真实下划线；检查代码还发现窗口未显式接收 mouseMoved，修饰键仅由代码文本第一响应者处理。开启窗口鼠标移动事件，并在窗口范围监听修饰键变化，使焦点在文件树时也能更新悬停；取消和过期请求仍由原有状态令牌控制。用户随后反馈“我测试可以了”，此项记为用户实测通过。

## 检查点

- Markdown 标题、列表、链接、代码高亮、长内容滚动、模式切换、刷新和清空均需覆盖。
- 按住与松开 ⌘ 不移动鼠标、文件树持有焦点、未知符号，以及普通 hover 都要区分验证。
- 补齐缺口后再完成测试与提交，遵循 AGENTS.md 的推送要求，不默认将初始版本视为例外。

## 工具受限的 UI 验证

用户进一步纠正：确实无法做到的 UI 验证标记为“需要用户验证”，以后不要自行重复尝试。此前对持续按住修饰键的窗口验证，在已经确认工具能力限制后仍尝试多个等价组合，未增加有效证据。之后应记录具体受限动作并停止同类尝试，继续能独立完成的验证；收到用户实际反馈后，以用户验证身份更新结果。

# 被忽略文件仍应可浏览，检索范围单独维护

## 用户纠正与预期

用户明确要求不要隐藏 gitignore 内容：Files 中仍展示并可展开、阅读，但不参加全局搜索和文件匹配。不能把“忽略检索”理解成“不允许浏览”。本次范围同时覆盖侧栏筛选、⌘P 和全文搜索，保留 Git 内部元数据的原有处理。

## 原因

旧实现让 Files、Quick Open 与项目搜索共用 WorkspaceState.files。在磁盘扫描前剪掉 Git 忽略路径以及 node_modules、dist 等目录，既隐藏了内容，也使浏览与检索不可分别控制。该原因已通过调用链核实。

## 修正措施

磁盘列表记录可见目录、可见文件与独立的 searchableFiles。忽略目录保留节点并延迟到展开时读取下一层，依旧不在初始扫描中递归；使用 Foundation 的目录读取与 Git 原生忽略规则，不手写解析器。Files 查询、Quick Open、全文搜索与最近文件候选仅使用 searchableFiles；展开和阅读忽略文件不会扩大候选范围。

已展开的忽略目录或已读文件纳入变化监听；未展开的依赖／生成目录后代不导致扫描风暴。刷新保留展开层级，重开目录重新取当前磁盘子项。未扫描的内容通过数量加号说明，不编造完整总数。符号链接不递归，目录读取继续检查工作区边界。

## 检查点

- 分别验证浏览可见／点击阅读，与侧栏筛选／⌘P／全文搜索排除，不能只验证一种列表。
- Git 忽略的普通文件、完整目录、已跟踪例外，以及未写入 gitignore 的生成目录均需覆盖。
- 大型被忽略树未展开时不读取后代；展开某层只读下一层，不通过全面递归来恢复可见性。
- 目录内容更新、切模式、清空筛选和重启恢复后不能产生旧节点、错位点击或漏目录；不对普通文件调用 skipDescendants。
- 自动化与实窗分别记录，未完成的项目不能提前声称通过。

## 首轮验证结果（修复前）

204 项完整测试与发布构建通过。实窗确认忽略内容可浏览，侧栏筛选、⌘P 和全文搜索仍排除，依赖目录与源码外部变化可自动同步。另发现 FileTreeIndex 的目录占位条目被当作自身子项，造成空白行；已定位并保留截图。按验收约定未改源码或测试，已请求用户授权修复，最终 UI 尚未通过。

## 目录占位空白行修复

用户明确要求修复并重新验收后，新增回归先在旧实现中复现：src/ 被列为 src 的子文件，空目录也产生空名称行。原因是前缀扫描遇到等于当前目录前缀的占位路径时，剩余部分为空，却仍构造了 FileTreeEntry。修正为只跳过当前目录自身的占位条目，继续保留真实的下一层目录与文件；补充普通目录、嵌套空目录及真实 NSOutlineView 行内容断言。后续新增目录占位表示时，必须验证其自身不能进入子项列表；“可见目录存在”与“展开后子项正确”应分别检查。重新验收结果另行补录。

## 修复后验证结果

回归先复现旧实现的 5 项断言失败，修正后通过；205 项完整测试零失败、零跳过，发布构建通过。代理实窗确认普通、忽略和空目录不产生空白行，筛选清空、模式切换、刷新、正常退出后重开均未复现。忽略目录可逐级展开阅读，但侧栏匹配、⌘P 与全文搜索仍排除忽略文件；已跟踪例外保留检索能力。重开时确认了项目、文件标签和非空忽略目录展开层级，不把未验证的空目录展开状态或非零滚动位置算作通过。复验期间冻结的 149 个源码、测试等文件指纹未变，详细结果见 docs/verification/2026-10-26-ignored-files.md。

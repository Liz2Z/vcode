# 更新签名与密钥输入框不能产生凭据回显

## 问题与预期

接入 Sparkle 时，浏览器提交 Secret 后立即读取完整辅助功能树；页面尚未跳转，工具返回了 Secret 文本框中的私钥。该钥尚未嵌入任何发布版本，但不应继续使用。敏感字段提交后只能检查成功页面或经过过滤的非敏感状态，不能截图、输出整个页面或输入框。

## 原因与修正

原因已核实为页面异步提交，点击返回不代表导航完成。已在本地生成替换密钥，更新同一个 GitHub Actions Secret；产品仅嵌入替换公钥。旧钥不提交、不用于发布，不将私钥或可还原内容写入文档。首次上传与替换的实际成功情况以 GitHub 成功提示及后续 CI 签名匹配验证分别记录。

用户明确允许仅对 Sparkle 内部存储例外，已补充 AGENTS.md；不能把引入第三方库等同于默认豁免 XDG，也不能为遵守 XDG 而擅自维护缺乏验证的 Sparkle 分支。更新包与清单使用框架原生签名工具；不自行编写安装器或版本比较。

## 检查点

- 密钥提交后等到已离开编辑页再观察，所有可能包含敏感字段的读取先过滤并关闭默认输出；只记录 Secret 名称、成功提示和更新时间。
- 私钥只通过专用文件或标准输入交给签名工具，禁止放在命令行参数、仓库和产物中。
- 本地匹配公钥与签名，并核对云端签名匹配，避免 Secret 与产品公钥不一致。
- 已公开仓库的审查覆盖本地可达历史；不能把凭据扫描未命中描述为绝对安全保证。此次 Gitleaks 扫描未命中，匿名 GitHub API 已确认仓库 private=false。

## 更新检查入口应沿用框架交互

UI 验收发现 Sparkle 在检查中仍允许通过菜单聚焦当前进度窗口，而新写的用例未经确认就要求禁用菜单。用户明确选择沿用 Sparkle、修正用例并重新验证。这里只修订用例，不为满足自定预期去改成熟框架的产品交互。重复点击应聚焦同一个会话，不能生成重复请求或下载；重新验收结果另行记录。

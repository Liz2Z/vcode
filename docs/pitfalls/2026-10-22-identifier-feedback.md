# 标识符的几种反馈必须分开

## 用户纠正后的预期

普通 hover 不加样式；⌘悬停且可以跳转时才加下划线；普通点击通过背景色展示当前文件中该语义符号的定义与引用；跳转目标以背景高亮／清除交替闪烁 2 秒。

## 原因与修正

原实现把普通 hover 与临时背景绑定，没有点击后的语义引用高亮；跳转动画只调节深浅，最低仍有背景，无法真正呈现取消状态。

改用四个独立状态：类型提示、经定义查询确认的 ⌘ 下划线、documentHighlight 返回的文件内符号背景、带独立计时器的目标闪烁。使用现有 TypeScript LSP 的语义能力，不能用全文同词匹配代替引用关系。跳转可用性与应用实际能打开的范围一致。

## 防止再犯

- 覆盖按住和松开 ⌘ 时鼠标不移动、无定义符号、旧查询晚返回、切换文件和相同文本的新工作区。
- 点击结果必须包含声明与引用，同时排除遮蔽作用域中的同名符号以及注释、字符串。
- hover 关闭不能顺带清除点击高亮；跳转闪烁清除不能擦掉下划线或修改源码语法属性。
- 闪烁的关闭阶段必须没有背景，完整重绘包含圆角留白的范围，结束后没有细边残留。
- 只重绘可见区域，不为每个屏幕外引用强制创建字形布局；旧状态与请求在文件替换时清理。

## 本次核验

- 86 项自动化测试通过，包含原生鼠标／修饰键事件、迟到结果隔离、UTF-16 与 diff 行映射、真实 TypeScript documentHighlight 的作用域区分及 2 秒闪烁计时。
- 独立窗口确认点击外层符号只高亮其导入与两处引用，局部同名变量、字符串和注释不混入；点击局部变量替换为局部定义与引用；点击空白清除。
- 最终构建确认 ⌘点击跨文件跳转，已捕获目标背景出现与取消的画面，结束后无目标背景残留。
- ⌘悬停曾因窗口工具不能单独持续按住修饰键而需要用户验证；2026-10-22 用户反馈“我测试可以了”，此项已由用户实测确认。原生事件测试通过与用户实测分别作为证据，不宣称代理捕获了该画面。

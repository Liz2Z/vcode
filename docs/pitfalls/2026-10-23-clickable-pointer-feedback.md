# 可点击反馈需要包含鼠标指针

## 最新结论：用户验证通过

首次悬停修正版打开后，用户确认“这次可以了，提交吧”。文件树和暂存分类不必先点击即可显示手型，现记录为**用户验证通过**；下文旧构建的失败保留作为过程记录，不再作为当前结论。该确认不扩展为全部控件、硬件滚动或所有窗口焦点组合均已验收。按用户指令提交当前改动，不推送。

## 旧构建用户验证失败：文件树必须在点击前更新指针

用户实测文件树及 Staged Changes 仍是普通光标，并进一步明确“移上去普通，点击后才变成手”。该路径现为**用户验证失败**，不能继续归类为工具限制或待确认。此前注册区域及 hasClickAction 策略的自动化没有覆盖首次进入与移动事件，不能证明原生事件流程的最终外观。

纠正后的预期是所有文件／目录和 Staged／Unstaged 分类，在未选中、未点击时移入就显示手型；文字、展开箭头和整行留白一致。追加回归覆盖进入、cursorUpdate 和移动，确保悬停不触发选择／激活，空白与禁用列表恢复箭头。旧实现只在行子视图注册 cursor rectangles，FileOutlineView 自身的移动路径只更新背景，没有主动设置手型；具体 AppKit 内部覆盖时序尚未核实，不写成已经确认的系统根因。

修正由 FileOutlineView 统一管理完整可见行宽的指针区域，并在进入／移动／cursorUpdate 后按当前位置设置，空白和禁用区恢复箭头；行视图不再为 outline 重复注册。原 hover 区域只在 key window 激活，也无法覆盖窗口首次激活前的悬停。现分为 activeAlways 的进入／移动区域和 activeInKeyWindow 的 cursorUpdate 区域：本机 AppKit SDK 的 NSTrackingArea.h 明确 activeAlways 不支持 cursorUpdate，不能把两个选项混用。布局时主动更新仍只限 key window，避免后台布局覆盖其他窗口的指针。新增用例先在旧实现复现失败，再验证未点击、未选中状态及两类跟踪选项；实际硬件事件的最终外观仍以用户实测为准。

## 问题与预期

用户指出可点击元素悬停时应切换为手型。原先主要统一了背景 hover／active 状态；FeedbackButton、标签和可激活列表行没有注册手型区域，可点击性提示不完整。

可点击按钮、标签（含留白和关闭按钮）、文件树整行及可打开结果显示手型；禁用控件、静态标题、不可用或当前工作区条目和列表空白不误导为可点击。目录和 Changes 分类可切换折叠状态，仍应显示手型。代码和输入保持文本指针，分隔条保留既有左右调整指针。

## 修正措施

使用 AppKit 原生 cursor rectangles，按 visibleRect 注册，不用全局事件监听或 mouseExited 强制覆盖下一个视图的指针。按钮共用 PointingHandButton；标签留白单独覆盖；共用行视图按所属表格、分组、选择策略及启用状态判断。禁用按钮和工作区切换时主动失效指针区域，滚动布局沿用原生裁剪并刷新标签区域；Git 列表额外排除当前和不可用目标。

## 检查点与验证边界

- 覆盖按钮／文字／图标／留白，以及目录、Changes 分类、结果行；不可用行和纯分组标题不能注册手型。
- 注册范围以当前可见区域为准，滚动和筛选后不残留；禁用和重新启用必须使旧区域失效。
- 不改变点击、拖动、源码选字、⌘跳转或分隔条行为。
- 自动化只能验证原生区域注册、策略与失效调用，不能替代屏幕指针外观。既有工具无法捕获真实指针的限制继续标记“需要用户验证”，不重复尝试同一受限操作。
- 完成代码和测试后固定构建验收；UI 阶段不修改产品或测试代码。验证结果后续单独补录。

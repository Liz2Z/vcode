# 不要因窗口截图裁切重做原生浮层

## 问题与纠正后的预期

输入框样式验收时，worktree 原生浮层左侧在应用窗口截图中未完整显示。后续尝试将 worktree／分支的 NSPopover 改成窗口内浮层。用户纠正“我觉得没必要吧，之前那样挺好的”，要求保留原来的体验。本次改造撤回，之前完成的输入框圆角、垂直居中和快捷键列表保留。

## 原因

原生 NSPopover 可以超出所属主窗口，应用窗口截图不一定包含整块浮层。此前只观察到了截图裁切，没有核实是否存在实际屏幕裁切或用户操作障碍；实际原因仍未核实。将截图范围问题直接扩大为浮层架构改造，超出了用户当前认可的交互范围。

## 修正措施

恢复原来的 NSPopover 展示与事件处理，移除本次新增的窗口内浮层测试及相应 UI 预期。恢复后核对先前固定版本的 111 项文件指纹，全部一致，确认此前的产品、测试和构建均保留。本次没有重新进行实窗验收，不宣称裁切问题已修复。

## 防止再犯的检查点

- 区分窗口截图范围、主窗口边界和实际屏幕边界；截图缺失不能直接证明真实界面不可用。
- 用户认可现有原生交互时保留现状，不因未核实的显示推断更换展示机制。
- 撤回当前尝试时只撤回当前改动，核对已有功能与测试，避免覆盖此前未提交的工作。
- UI 验收阶段只验证并记录，不能自行修改产品或测试代码。

# JSON 文件开头被行号栏遮挡

## 问题与预期

用户截图指出打开 JSON 后前面一段内容被遮住。预期大括号、首个键名及缩进在文件初次打开、标签往返、历史恢复及刷新后均完整显示；主动水平滚动的阅读位置仍应按文件恢复。

## 已确认原因

回归复现：短 JSON 初次打开正常，切到其他 JSON 再回来后，开头文字的横坐标从行号栏右侧变为行号栏内部。原生 NSScrollView 将行号栏叠在 clip view 内，通过 clip view 的 contentInsets.left 预留空间；当前环境该值为 58，因此未水平滚动时的 bounds.origin.x 是 -58。原位置恢复使用 max(0, …)，将合法的负值改为 0，正好把开头 58 点文字移到行号栏下面。仅断言字形处于 text.visibleRect 内会错误通过，必须同时检查行号栏与字形在同一坐标系下的位置。

此外，原新内容加载用 diff 同步方法归零，该方法有意只同步纵向位置，不适合初始化另一个文件的水平位置；长文件之间切换不能依赖短文档缩小时偶然夹取滚动值。

## 修正措施

恢复位置交给 NSClipView.constrainBoundsRect 按当前文档及原生 insets 约束，不再假定最小水平坐标为 0，也不硬编码 58。新内容初始化单独重置两轴，从原生 contentInsets 的起点显示；随后若有当前文件保存的阅读位置，按原记录恢复。diff 两栏的日常同步仍只同步纵向位置。

## 检查点与验证边界

- 回归实际重复打开同一文件，而不只打开不同路径；覆盖短 JSON、长 JSON、从已水平滚动的 TS 切入 JSON、刷新及源码／diff 往返。
- 检查大括号和首个键名的字形位置在行号栏右侧；保留跨文件历史恢复的原水平位置测试。
- 自动化与实窗结果分别记录；本文写入时实窗复验尚未执行，不能提前宣称通过。UI 验收固定构建后不再修改产品和测试代码。

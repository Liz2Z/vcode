# 新 Worker 的 Shell 基线需单独核查

## 问题

用户要求参照 idev005 准备新机器，环境初始化仅配置了运行时 PATH，遗漏了交互式 Shell。用户指出 idev007、idev008 没有对齐 Oh My Zsh。

## 纠正后的预期

将 Oh My Zsh、主题、插件和交互设置纳入参考机差异检查；修改前列清单并等待用户确认。Worker、Monitor 继续保持停止，开机项禁用。

## 原因

初始化检查聚焦于非交互 SSH 下的运行时与 CLI，未检查 `.zshrc` 和 Oh My Zsh，误将 PATH 就绪视为 Shell 环境已对齐。

## 修正措施

已确认 idev005 使用 zsh、Oh My Zsh、fino 主题、10 个插件及历史记录、自动建议和语法高亮设置；两台新机器原先均缺少 `.zshrc` 与 Oh My Zsh。用户确认后，已安装与参考机相同提交的框架和两个外部插件，并同步通用交互设置，保留原有 `.zshenv`、`.zprofile`。未复制参考机的历史、可选应用路径或个人别名。

验证使用两台机器各自的新交互 SSH 会话完成：真实登录提示符显示 fino，输入命令可见语法高亮，再次输入命令前缀可见历史自动建议；另检查了插件加载、Git 补全、Ctrl-R 绑定、历史与目录切换选项、运行时和 CLI 路径。Worker、Monitor、PM2 均无进程，开机项仍禁用。通用 SOP 已加入安装与验收步骤。未进行整机重启复验，本次不据此宣称重启验收通过。

## 防止再犯的检查点

- 参考机对齐必须分别检查登录 Shell、交互 Shell 与非交互命令环境。
- 核对主题、插件版本及交互行为，不只检查运行时 PATH。
- 不直接复制参考机的历史记录、身份凭证、机器专属路径或未经审阅的自定义脚本。
- 配置后用新交互 SSH 会话检查插件、主题和命令路径，并确认没有启动 Worker、Monitor 或 PM2。
- 完成安装后更新通用 SOP；单机状态与执行历史不写入 SOP。

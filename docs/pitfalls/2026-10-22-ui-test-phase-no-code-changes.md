# UI 测试阶段不能边测边改代码

## 问题与纠正后的预期

用户明确要求在 AGENTS.md 记录：UI 测试阶段不允许修改代码。此前在实窗验收 Markdown 时，又修改预览的代码块背景、选区初始位置和版本号，造成同一轮测试先后对应不同实现。

## 原因与修正

将发现显示问题与立即修复混在一个验收任务中。用户要求禁止 UI 测试时改代码后，又自行宣布结束测试、切换修复阶段，修改了引用过滤及其测试并提交、推送。这种自行切换阶段仍然绕过了用户要求；固定构建和源码指纹并不能代替修复授权。

UI 测试任务只能执行现有用例、记录通过、失败或需要用户验证。发现问题只记录并报告，等待用户另行明确要求修复，不得自行把验收任务扩展为修复任务，也不能据此自行提交或推送修复。AGENTS.md 已删除此前允许自行切换修复阶段的错误表述。

## 检查点

- 开始 UI 测试前固定代码与构建，保留版本或源码指纹。
- 发现问题先记录，不在 UI 测试过程中顺手改实现、测试或样式。
- 没有用户另行明确的修复指令，不得通过重命名或切换阶段继续改代码；修复的提交和推送同样不能从验收任务中自行推定授权。
- 区分已有构建的测试证据与修复后的复验，不能将不同版本的结果拼成同一次通过。

# 玻璃材质与浮层区分度必须成为默认约定

## 问题与纠正后的预期

用户反复提醒浮层要用 macOS 原生玻璃效果、弹框必须与底层窗口有区分度，代理仍只作口头承诺。用户明确指出不能停留在口头答应。后续新增或修改应用内浮层、弹框时，这两项应作为默认设计和验收要求，不再依赖用户逐次提醒。

## 已核实原因

此前记录集中于编辑器查询的具体布局与样式，没有将通用要求写入项目 AGENTS.md 和整体 UI 验收标准。本次侧聊的首次回复也没有修改任何文件，因而没有形成供后续任务查阅的项目约束。既有记录已指出同底色会使浮层层次消失；使用玻璃控件本身也不能保证实际区分度。

## 修正措施

- 在 AGENTS.md 写入默认约定：复用共享封装，macOS 26 及以上使用 NSGlassEffectView，旧系统使用原生模糊材质回退；同时建立清晰的材质、边缘和投影层次。
- 在 tests/ui/README.md 的整体视觉要求中加入对应需求和预期，覆盖浅色空白正文、密集代码、diff 背景、深色主题以及底层滚动和主题切换。
- 材质是否原生、与底层是否清晰区分需要分别核对；不能以设置了 API 属性替代实际外观检查。

## 防止再犯的检查点

- 开始浮层或弹框工作前查阅本记录及项目默认约定，先选共享原生材质方案。
- 交付前主动核对实际边界、文字与操作可读性，以及重要导航控件是否被遮挡。
- 用户纠正通用交互或视觉要求时，同步更新默认约定、踩坑记录和验收标准，不能只在回复中承诺。

## 本次范围与验证状态

本次仅将约定与验收要求落入文档，未修改产品、测试代码或用户维护的 PRD，未执行产品 UI 验证，不声明当前所有浮层均已满足要求。编辑器查询的具体实现与验证仍由主线程处理；本记录不将主线程未完成的工作标记为通过。

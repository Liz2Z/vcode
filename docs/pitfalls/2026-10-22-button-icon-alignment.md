# 按钮图标与文字必须共同布局

## 问题与纠正后的预期

用户指出 Files 与 worktree 等按钮中的图标经常显示错位。仅调整按钮外框和内边距不足以满足预期：图标必须完整清晰，与文字垂直居中，图文间距稳定；长名称只能压缩文字，状态切换不得改变几何位置，整个按钮都能点击。

## 原因

已核实旧实现把自绘反馈背景、自定义 cell 内边距与 NSButtonCell 的图文绘制组合使用，没有独立约束图标区域、图文间距及文字压缩策略。先前仅验证实际按钮外框，未检查内部图标、文字布局及最终显示。截图中每次错位的具体数值和触发条件未单独复现，不能将全部现象断言为某一个原生偏移值。

## 修正措施

共享 FeedbackButton 使用原生 NSImageView 与单行文本组成同一个居中布局，固定图标容器，明确图文间距和左右内边距；长名称在文字区域中间截断。背景仍负责交互反馈，原生按钮保留 action 与无障碍语义，避免 cell 再绘制第二份图标和文字。纯图标按钮继续保持正方形和居中位置。

## 验证与防止再犯

- 检查布局后的内部图标、文字矩形及实际渲染，不能只检查按钮外框。
- 覆盖短名称、长名称、窄宽度、禁用和选中状态，以及 hover 状态切换后位置是否稳定。
- 图标、文字与留白属于同一个点击区域，不应被新增内容子视图截获。
- 本次编译、内部布局回归测试及窄宽度工作区布局测试通过；独立原生窗口检查了普通、选中、程序化 hover 预览和长名称显示，并实际点击图标与文字确认 action 生效。
- 程序化 hover 预览与真实指针移入不是同一种验证；本次未稳定捕获真实指针移入后的 hover 背景，不能宣称该项已经实际窗口验证通过。
- 对应需求与预期同步写入 tests/ui/README.md；该文件不承载运行命令或执行历史。

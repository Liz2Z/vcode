# 可编辑草稿和只读源码的状态提示必须同步

## 问题与纠正后的预期

新建可编辑标签的实窗验证发现：草稿切回项目源码后，正文确实只读，底部却残留“Editable text · ⌘S to save”。用户明确要求修复并重新验证。切换文件、历史跳转及切换编辑器分栏焦点后，应立即显示当前文档的编辑模式，不能依赖再次点击正文来刷新。

## 原因

已核实：草稿激活回调写入 Editable 提示，源码打开只更新语言服务状态，没有重置左侧提示；原有光标回调或工作区刷新之后才会覆盖它。

## 修正措施

集中更新编辑模式提示，在文档切换、草稿激活、分栏焦点变化和工作区刷新时调用；后台加载非当前编辑器时不改变当前组的模式。补充对应控制器回归测试与 UI 预期。修复得到明确授权后执行；新的实窗结果另行记录，本文不将未验证行为写成通过。

## 防止再犯的检查点

- 同时检查实际可编辑状态、状态文字和菜单可用性。
- 切换后先观察，不点击正文，防止点击掩盖状态残留。
- 双分栏分别打开只读源码和可编辑草稿，往返聚焦检查。
- UI 验证发现新问题时只记录报告，收到明确修复指令后再修改代码。

## 修复后验证

最终 16 项草稿／标签相关自动化测试与发布构建通过。固定预览实窗确认：直接选择源码标签即显示 Read Only，不需要点击正文；草稿与只读源码两栏往返聚焦时，模式提示同步。最终 UI 阶段产品与测试文件指纹无变化。其他验证范围见 docs/verification/2026-10-26-editable-tabs.md，不扩大本条状态修复的通过结论。

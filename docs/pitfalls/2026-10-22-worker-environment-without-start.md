# Worker 环境初始化不包含服务启动

## 问题

环境初始化清单将安装、配置开机启动和启动 Worker、Monitor 合并，用户明确纠正：Worker 和 Monitor 不得启动，启动服务不属于本次环境配置。

## 纠正后的预期

准备运行时、工具、仓库、依赖、CLI、Skills 和节点配置。开机启动文件只生成，不加载或启用，避免后续重启时未经确认就启动服务。

## 原因

清单沿用了运行部署的验收方式，将注册和持续心跳当作初始化验收，混淆了环境准备与服务上线的边界。

## 修正措施

将验收限定为版本、可执行路径、依赖与配置检查；核验 Worker 和 Monitor 无进程、无监听端口、未向 Core 注册。服务启动、启用开机自启和运行态验证另行确认。

## 防止再犯的检查点

- 初始化不执行 PM2 start、resurrect、startup、install 等可能启动受管进程的命令。
- 检查安装脚本和 package lifecycle 是否包含服务启动副作用。
- 生成启动文件时同步保持 launchd 服务禁用，禁止 bootstrap 或 load。
- 不复制其他机器的 PM2 dump、会话、认证缓存或私钥。
- 已验证运行时版本、CLI 构建、节点配置校验和依赖加载；已核实开机项禁用且未加载、Worker 端口无监听、Core 未注册新节点。初始化阶段未执行服务启动。

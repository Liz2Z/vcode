# 文件独立撤销记录必须接入菜单响应链

## 问题与纠正后的预期

普通文件编辑的用户验收反馈“撤销重做好像没用”。原先回归直接调用 text.undoManager.undo／redo，通过后只证明记录存在，没有证明 Edit 菜单、⌘Z 和 ⌘⇧Z 能使用这份记录。应由当前焦点编辑器使用当前文件的撤销记录；查询输入框使用自己的原生撤销，diff 不执行编辑撤销，不能串到其他文件或分栏。

## 已核实原因

CodeTextView 覆写 undoManager 为文件独立的 documentUndoManager，但没有实现 undo:／redo:。App.swift 的菜单使用 target=nil 的标准选择子，响应链最终由 NSWindow 接收；窗口仍持有另一份原生 undoManager。NSTextView 默认不响应这两个选择子。已有单元测试绕过响应链直接调用文件管理器，未覆盖真实入口。

独立原生诊断 `.build/diagnostics/source-undo-20261028/manager-probe.swift` 复现：文件管理器 canUndo=true，窗口管理器 canUndo=false，两者身份不同；向窗口发送 undo: 返回已接收但正文仍为 typed，直接调用文件管理器才清空正文。这是原生诊断和源码核对，不冒充最终预览中的实际快捷键验证。

修复回归进一步核实重做菜单绑定的问题：原菜单用小写 z 配合 command／shift 标志，AppKit 不会据此匹配字符为大写 Z 的真实 ⌘⇧Z。独立 `menu-key-probe.swift` 对比 keyEquivalent、characters 和 charactersIgnoringModifiers 的组合，确认重做的 keyEquivalent 应为 Z；只修改 modifierMask 不足以保证可用。首轮测试构造的 Shift 字符也不正确，曾误触 Undo，后续保留断言、修正为真实事件字符，未将这一轮记为通过。

## 修正措施与验证边界

用户明确回复“修复并重新验证”后，在 CodeTextView 接入标准 undo:／redo: 动作及相应菜单可用性，使有焦点且可编辑的文本视图使用自身记录；继续保留每个文件的独立记录和查询输入框的原生行为。标准 Undo／Redo 菜单集中定义在 StandardEditCommands，应用与回归复用同一份绑定，重做使用大写 Z。菜单动作和 NSMenu 的 key-equivalent 分发回归覆盖普通文件、切文件、分栏、草稿、查询输入框和只读 diff，不再只调用管理器。

XCTest 未运行 NSApplication 的主事件循环，故测试明确从已聚焦 responder 解析 action target，再经真实 NSMenu 发动作／key equivalent；不把这一过程表述为完成了独立应用中的系统键盘实测。最终完整检查与固定应用实窗结果另记。

修复后完整统一检查 272 项、0 失败，报告 `.build/check-results/20261028T072754Z-77600/`；发布构建通过。在固定独立预览 VCode Undo Fix 中，工具经 System Events 聚焦实际正文，输入 edit，按 ⌘Z 恢复磁盘原文，再按 ⌘⇧Z 恢复刚输入的内容，逐步读取实际控件文本核对通过。重做后标签圆点与 Edited 说明正常，磁盘文件尚未改动。这是修复版本的代理实际键盘验证。

随后检查 Edit 菜单点击时，正文出现本轮操作没有输入的 61；与输入前后快照不一致，来源未核实，不能将断言不符直接认作产品菜单失败或宣称菜单通过。已停止继续输入，保留当前内容并请用户单独确认菜单撤销／重做。不使用受其他输入干扰的结果覆盖上述独立按键验证，也不把用户尚未回复的项目记为通过。

用户最终针对新版 VCode Undo Fix 的 Edit → Undo／Redo 及正文、未保存圆点变化，明确回复“菜单撤销和重做都正常”。菜单入口据此记为用户实测通过，与此前代理实际快捷键验证共同完成本次撤销／重做修复的验证；不冒充代理完成了受干扰的菜单实测，也不扩大为普通文件编辑全部功能已验收。

## 防止再犯的检查点

- 单独核对记录生成、动作响应目标和菜单验证，不能以 canUndo=true 代替快捷键可用。
- 通过实际菜单动作或 key-equivalent 分发检查 ⌘Z／⌘⇧Z，验证正文、未保存标记和共享工作副本同时更新。
- 查询输入框与正文往返聚焦、同文件双栏与跨文件切换时分别检查，不将撤销送到非当前文档。
- 用户指出验收问题时明确记录为未通过，旧版本自动化通过不能覆盖用户实测失败。
- 应用与回归复用实际菜单定义；Shift 组合必须核对字符本身及修饰键，不能用与真实事件不一致的构造掩盖绑定错误。

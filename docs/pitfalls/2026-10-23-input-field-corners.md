# 输入框圆角统一

## 问题和纠正后的预期

用户指出项目搜索中的查询框为胶囊形，目录排除框为小圆角矩形，要求项目所有输入框使用后者。范围包含侧栏与浮层中的搜索／筛选和普通文本输入，不是只修截图里的两处。

## 原因与修正

原实现分别直接创建 NSSearchField 和 NSTextField；原生搜索框默认使用 roundBezel，普通文本框使用 squareBezel，造成同一界面外形不一致。原生控件绘制对比已核实该差异。

统一通过设计系统 Theme.inputField 创建输入框并使用 AppKit 的 squareBezel。覆盖 Files／Changes 文件筛选、全文搜索与目录排除、快速打开、最近项目、分支／worktree 与快捷键筛选。保留原生 cell、搜索和清空按钮、文本编辑及辅助功能，不通过裁切胶囊背景伪造圆角，也不改动只读标签和代码视图。

## 防止再犯的检查点

- 新增搜索／文本输入时使用同一设计系统入口，不能只比较同类控件而忽略同屏搜索框与普通输入框。
- 不通过增大圆角到半高、仅裁切视图或自绘替换原生搜索行为处理外形。
- 对照侧栏和各浮层的空值、有值、聚焦、清空与禁用状态；验证图标和文字不裁切，宽窄布局仍为小圆角。
- 完成实现和构建后固定版本验收，UI 验收阶段不修改产品或测试代码；未能完成的项目单独标明。

本次验证结果待补录，不能沿用此前胶囊形输入框的实窗结果。

## 用户纠正：输入内容全部偏上

小圆角初版的 36 项相关回归及发行构建通过；固定构建实窗已检查 Files／Changes、全文搜索与排除、快速打开、分支／worktree、最近项目的矩形外形，并验证查询、排除、清空、筛选与 Return 打开。快捷键输入框本轮尚未完成外观检查，不能写成全部验收完成。用户随后截图指出 Filter files 的文字和图标偏上，要求所有输入框垂直居中；这是明确的新增修复指令，按该指令停止旧版验收并开始修复，不从 UI 验收自行推定修复授权。

已核实：方形 bezel 的 28 pt 原生控件仍按较小的原生内容高度从顶部布局；12 号字体的原生文字矩形为 y=4、高20，实际单行字体高度15，导致文字偏上，图标矩形的中心也不在输入框中心。只修改 bezel 未检查内部内容与编辑光标，是本次遗漏。

修正：共享搜索框通过 AppKit 公开的 searchTextBounds、searchButtonBounds 和 cancelButtonBounds 同时居中文字和按钮；普通文本框通过原生 cell 的 drawingRect 居中显示和编辑区域。文本高度取实际字体的单行度量，不写死某个字号的 y 偏移；保留原生横向留白、按钮功能和辅助功能。对 26／28／30 高度、不同宽度、空值及有值、聚焦编辑与失焦增加原生几何回归，并重新固定构建验收。新一轮结果待补录。

检查点追加：不能只比较外框圆角；应检查占位提示、实际文字、搜索／清空按钮和插入光标的上下留白，且所有入口均适用。

新版验证补录：38 项相关自动化通过，包含不同高度／宽度／字号下的文本与按钮几何、原生 field editor 位置及选区，发行构建和深层签名检查通过。固定构建实窗确认 Files 占位及输入后的文字、图标、清空按钮和光标居中；Changes 筛选框为同一矩形样式。项目搜索与排除框输入、排除后 2 条变 1 条、清空查询、Quick Open 输入和 Return 打开、分支筛选、worktree 筛选、Recent 筛选及快捷键 project 查询正常，所见文本与光标均居中。截图覆盖各处；worktree 浮层左侧超出预览窗口／截图边缘，完整左侧图标外观未能确认，作为独立 UI 显示失败记录，未在验收阶段修复。物理宽窄拖动沿用工具限制，标记需要用户验证且不重复尝试；busy 禁用外观本轮未做实窗验证。最后一组额外清空／关闭操作被用户实时界面变化中断，重新观察后停止该组，不记录为通过。111 项固定文件在本轮验收前后无变化，之后仅追加结果文档；没有在 UI 阶段修改产品或测试代码。截图与逐项结果位于本地 `.build/diagnostics/input-style/centered-*`。此次只验收输入样式及居中，不代表全应用 UI 全量通过；未提交或推送。

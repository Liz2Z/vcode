# 类型提示需要结构化渲染，跳转问题先验证

## 问题与预期

用户要求类型悬停具备类似 VS Code 的语法高亮、排版与窗口边界处理，并指定 12 号字体、Monaco 优先且 Menlo 回退。用户随后确认现有多层级定义跳转似乎已经可用。

预期：标识符上显示具体类型；类型代码保留缩进和高亮，说明文档正常排版，超长内容可阅读；浮层不越过当前窗口和屏幕。保留已能工作的多级跳转，并以回归验证确认，不能先假定服务只能跳到顶级定义。

## 已确认原因与修正

旧实现将 LSP 悬停内容合并为字符串后，直接放入固定 480×160 的纯文本浮层，还截断为 6000 个字符。TypeScript 返回的 Markdown 代码围栏因此原样显示，格式和代码语法未参与渲染。新实现使用 Foundation Markdown 解析文档，用共享的代码高亮渲染代码块，并按窗口可用空间布局可滚动的浮层。

直接查询真实项目的 TypeScript 服务，嵌套 `get()` 能返回 `libConf.ts` 中的成员声明；因此不把多层跳转整体判为缺失。鼠标定位改用实际字形及其标识符范围，避免最靠近的插入点落在点号或相邻成员上。

## 防止再犯

- 保留协议中的代码块语言和内容结构，优先复用原生 Markdown 解析能力。
- 分别验证短签名、嵌套对象、长行、长文档，以及窗口四角的位置和滚动阅读。
- 鼠标移开、滚动或切换文件时，使旧请求失效；移动到浮层里阅读时不能立即关闭。
- 诊断定义跳转时，先检查实际点击位置和 LSP 返回，再区分成员、生成类型、跨文件路径及跳转后的继续操作。
- 更换字体后核对真实字形行距；Monaco 自带 leading，行号、文字和 diff 背景必须使用一致的行高。

## 悬停提示的停留与关闭

用户纠正：离开标识符后应保留提示 2 秒，移入提示后保持显示，以便继续阅读详情；触发其他提示时替换旧提示。

已确认旧实现：代码内的标识符变化调用立即关闭，离开整个代码区域仅延迟 180 毫秒；提示表面只有移出回调，没有移入时取消计时。仅在计时结束时读取一次全局鼠标位置，无法明确维护从代码到弹框再移出的停留状态。

修正措施：指针移动与立即失效操作分开，离开时安排一次 2 秒关闭；进入提示或返回原标识符取消计时，离开提示重新计时；新提示取消旧任务并校验任务令牌及窗口身份。滚动源码、切换文件、Escape 及其他操作弹框仍立即关闭。

检查点：覆盖代码内移出、跨越间隙进入弹框、持续阅读超过 2 秒、再次移出、返回原标识符，以及旧关闭任务到期时新提示仍显示；不能只验证静态截图。

实际窗口检查还发现，Recent 的原生 action 可以在未经过鼠标事件监视器时执行，旧提示仍叠在新浮层上。因此打开历史、Git 选择器和目录对话框的 action 必须主动关闭提示、取消待返回的 hover 请求；其他浮层存在时也不接受背后源码发起的新 hover。不能仅靠全局鼠标监听维护浮层互斥。

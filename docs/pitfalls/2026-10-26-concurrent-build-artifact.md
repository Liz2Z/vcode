# 并行构建不能共用待交付的 dist 应用

## 问题与预期

用户要求提供测试包后，直接从共享 dist/VCode.app 打包。另一路语言服务任务同时替换该应用并修改打包脚本，首次归档虽存在却不包含当前 minimap，脚本也因运行时文件被改写而中止。代理错误地把另一个从共享 dist 复制的窗口当成固定验收构建，延后发现功能缺失。

用户应拿到与已验收源码和实际窗口一致的应用，测试包具备要求测试的功能，不能只检查文件存在、签名或归档完整。

## 核实原因与措施

通过包内可执行文件的功能标记、机器代码和固定验收副本对照，确认首次包使用了其他构建。已告知用户作废旧包；改从此前独立验收应用复制，使用独立测试身份与 XDG 状态，使用冻结的打包脚本。新版归档检查功能标记、ZIP 完整性、机器代码一致性及签名。重新签名会改变签名数据，不能只凭整个可执行文件 SHA 不同认定代码不同。

完整测试也受动态依赖目录影响：默认语言服务连接未读取测试环境中的资源变量，回退到正被替换的 Tools 路径。使用独立 XCTest App 附带固定运行时后，两项受影响的集成测试通过，所有原失败记录保留。

## 检查点

- 交付从独立固定应用打包，包内能力与机器代码必须对应实际验收窗口，不使用共享 dist 的最新文件假定。
- 运行脚本前冻结其副本，不边执行边读取可能由其他任务改写的脚本。
- 并行任务源码、构建脚本和依赖不混入本次提交，不覆盖或撤销他人的修改。
- 运行时也属于测试输入，隔离源码还不够；明确记录环境失败与重新验证结果，不抹去失败历史。
- UI 验证中遇到未确认行为先记录，不能把工具选择成功写成文件已打开。

## 工具坐标核对补充

解锁后的文件切换检查中，截图确认工具输入坐标被按 2 倍 Retina 比例缩小，点击文件文字实际上落在筛选框左侧。依据当前截图校正比例后，同一文件行的物理点击成功切换右组源码；不能把 AX 选中成功当成激活，也不能在未核实坐标比例前将未切换认定为应用 bug。该比例仅属于本次窗口与工具会话，后续必须重新观察，不硬编码到产品或测试。

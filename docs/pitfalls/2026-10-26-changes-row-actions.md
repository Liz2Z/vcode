# Changes 操作按钮只在悬停时显示

## 问题与纠正后的预期

首版把 Changes 文件／目录的「+／−」按钮常驻展示。用户明确纠正：鼠标未 hover 时不展示按钮，并新增要求 Staged Changes／Unstaged Changes 分类标题也提供全部取消暂存／全部暂存操作。

纠正后的预期：仅当前悬停行显示按钮，选中但未悬停也隐藏；显隐不改变文件名、状态字母和分类计数位置。分类操作位于行右侧，点击不触发展开／折叠，空分类禁用，批量范围不受当前筛选或节点展开状态缩小。

## 原因

已核实：首版将“操作直接可见”的偏好直接解释为常驻按钮，没有遵循用户参考图中的上下文操作方式。分类批量按钮属于用户这次补充的能力，不将其遗漏描述成最初需求已经明确却未实现。

## 修正措施与检查点

收到明确纠正与补充指令后调整实现：树管理当前悬停行，按钮留出固定布局空间；Git domain 使用整个分类目标提供批量操作，UI 只传递目标与方向。补充悬停离开、选中后移出、分类按钮、空分类、显隐布局稳定及批量操作回归。

- 区分“直接操作”和“常驻展示”，以用户明确的 hover 规则为准。
- 鼠标跨行、移出树、滚动、刷新和控件复用后不残留上一行按钮。
- 分类计数贴标题，批量操作在右侧，两个布局彼此独立。
- 真实悬停若无法由工具捕获，明确标记需要用户验证，不反复尝试同一受限操作。
- 新构建的自动化与实际窗口结果单独记录，不能将首版常驻按钮的观察当作新 hover 行为通过。

## 文件夹按钮右侧的空状态列

用户再次指出文件夹操作按钮右侧无内容却留出整块空间。已核实原因：目录复用了文件行的按钮→状态标记约束，即使目录状态文字为空，仍保留至少 20 点的状态列及其间距。

纠正后的预期：文件保留状态标记及其前方操作；目录无状态标记，操作直接靠右，只保留正常边距；目录缩进不改变右端对齐，hover 显隐不引起名称跳动。

修正措施：按节点类型切换约束，目录隐藏状态视图并移除其布局占位。补充浅深层目录、反复缩放、hover 显隐及文件／目录复用的回归检查。此次修改后的自动化和实窗结果待验证，不能沿用旧版结论。

检查点：有内容才为尾部附件预留空间；检查最终可见边距，而不是只断言按钮位于一个空控件之前。

用户后续实际验证确认“边距和全部操作都正常”，目录操作右侧留白、分组全部暂存／取消暂存记为用户验证通过，不能写成代理实窗验证。

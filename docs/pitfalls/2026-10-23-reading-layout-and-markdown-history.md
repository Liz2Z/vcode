# 分支切换布局异常与 Markdown 历史位置

## 问题与预期

用户明确要求修复此前验收发现的两项问题，再进行验证。分支切换必须稳定更新源码和 diff；Markdown 后退应恢复可见段落，包括光标留在开头的情况。修复阶段结束后固定构建，UI 验收阶段不修改产品或测试代码。

## 已核实的原因与修正

分支切换自动化基线复现 AppKit SIGTRAP，栈位于 NSScrollView 的传统双滚动条角落视图插入及约束更新。源码模式仍恢复已移出界面的左侧 diff 面板；避免该操作本身尚不能解决崩溃。代码面板局部使用 overlay 滚动条后，原切换用例通过；不更改系统滚动条偏好，也不影响文件树独立占位的滚动条。

Markdown 的历史数据实际保存了 832 点，重新渲染时文本高度却只有 486 点，恢复位置被夹到 70 点。隐藏预览清空后，文本容器可能保留有限高度。恢复位置前将容器高度重设为无限并完成全文布局，同时明确文本可垂直增长；不以延迟重试掩盖问题。有限高度回归在修复前得到 64 而非 800，修复后通过。

- Markdown 回归应区分光标与视口，模拟隐藏预览遗留有限容器高度，确认全文布局后再恢复滚动位置。

## 用户补充：参考 VS Code 的内容位置与布局映射

用户指出应参考 AST／内容位置与行高、行数之间的映射，不能只围绕滚动数值修补。核对 VS Code 源码后需要区分：

- 普通编辑器 ViewModel.saveState 保存 firstPosition、firstPositionDeltaTop 和 scrollLeft；恢复时将模型位置转换为视图位置，再由当前布局计算纵向坐标。这条恢复路径不依赖语言 AST，折行等使它不能简单化为源文件行数乘固定行高。
- Markdown 引擎通过 markdown-it token.map 给渲染元素添加 data-line；scroll-sync 将源行号映射到渲染元素的真实边界，并在元素或代码块内插值。预览初始化另支持 scrollProgress，在内容和图片加载后按文档实际高度恢复；不能概括成所有导航均用 AST。

本项目代码面板已有文本上下文锚点、顶行与局部偏移；Markdown 当前只有选区及绝对 x/y，缺少源位置与预览排版的映射。后续修复方向应记录可见内容锚点，并在当前排版完成后映射回视口，明确等待期间状态不能被临时空内容覆盖。这是改进方向，不代表已经核实剩余失败原因；本次仅核对实现与补充记录，未修改产品或测试代码。

## 内容锚点修复阶段

用户明确要求按内容锚点与排版映射方向继续修复，并补充 TypeScript 源码也采用相同原则。本轮不沿用此前已失败的 UI 结果作为通过证据。

Markdown 使用 Foundation 原生解析器提供的源行列，给渲染文本保留源范围；记录首个可见文本的源位置上下文与行片段内的局部偏移，恢复时由当前 TextKit 排版映射回视口。解析器源列为 UTF-8 字节列，转换成 UTF-16 时保留中文、emoji 和 CRLF；当前系统的 NSRange(MarkdownSourcePosition,in:) 对完整文本跨度返回首字符范围，已通过独立样本核实，因此按解析器提供的行列转换，并增加完整范围回归。

将预览容器与文档尺寸统一交给预览视图管理，禁用 NSTextView 自动调整尺寸，避免两套尺寸机制互相覆盖；历史到达事件延至异步渲染、布局和恢复完成后发布，渲染期间继续持有待恢复锚点。TS 继续使用文本上下文锚点，但纵向映射改为查询 TextKit 真实行片段，不再直接用行号乘行高。

另查明此前可见窗口自动化仍可能只有 31 点宽、0 点高：设置 contentViewController 会改变测试窗口尺寸，而测试没有应用真实应用的最小窗口约束。已给相关回归设置有效尺寸并断言滚动区域宽高，禁止将零尺寸的通过当成真实布局已覆盖。最终实窗结果待固定构建后另行记录；剩余问题是否完整修复必须以本轮真实往返操作为准。

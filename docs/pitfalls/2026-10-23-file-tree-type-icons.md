# 文件树不用图标区分文件类型

## 用户纠正与预期

用户要求文件树不再使用图标标记不同文件类型。Files 和 Changes 的普通文件行直接显示文件名；目录继续保留展开箭头及文件夹图标，Git 状态标记保留。

## 原实现与修正

原实现按扩展名为 TypeScript 展示花括号、其他文件展示文档图标。移除这组类型判断与文件图标，并同步收起图标宽度和文字间距，避免出现空白占位。文件夹和分组的展示职责分开处理；复用文件／目录／分组行时重新设置图标状态。

## 检查点

- 检查 Files 和 Changes 中的 TypeScript、Markdown、JSON 等文件，无类型图标或残留占位。
- 目录图标、展开箭头、Git 状态和分组数量保持正确，窄侧栏、刷新与行复用后仍然如此。
- 本次修改仅针对图标展示；此前筛选后点击文件失效的问题仍单独记录，不能因布局变化后暂时恢复就宣称已修复。
- 固定构建后再做实窗验证，验收期间不修改产品或测试代码。验证结果如下。

12 项相关自动化测试通过；独立固定构建中实窗检查了 TypeScript、Markdown、JSON、Python 和普通文本文件。Files 与 Changes 均只显示文件名，没有文件类型图标或图标占位；目录图标、展开箭头、M／D／U 状态及两组数量显示正确。刷新和 Files／Changes 往返后保持一致；源码与测试指纹在验收前后完全一致。截图与执行记录位于本地 `.build/diagnostics/file-tree-icons/`。

## 用户补充：目录和打开文件标签也不要图标

用户进一步明确，目录图标及文件标签中的类型图标也要移除。上面的保留目录图标是先前版本的判断，不再代表当前预期。当前要求是：树中只有名称、目录展开箭头及 Git 状态；标签只有文件名、比较分类文字及关闭按钮。移除 FileCell 中整个图像视图与相关布局约束，不留下目录或文件图标占位；EditorTabs 不再根据扩展名选择图片。顶部 Files／Changes／分支等功能入口图标不属于本次移除范围。

## 补充要求的最终验证

最终固定构建实窗确认 Files 和 Changes 的文件、目录均无图标占位，打开的源码和 Unstaged 标签也只显示标题、分类文字及关闭按钮。目录展开箭头、Git 状态、分组数量与标签关闭仍可操作。刷新、模式往返和窄侧栏下保持一致；106 项自动化测试通过，UI 验收期间未修改源码或测试。截图与记录保存在 `.build/diagnostics/filter-click/`。

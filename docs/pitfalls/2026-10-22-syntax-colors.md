# 界面配色不能限制代码高亮的层次

## 问题与预期

用户指出代码高亮过于单调。原有高亮虽然区分了若干词法类别，但颜色集中在灰黄范围，类型、函数和字符串难以快速区分，属性大多仍是普通文字颜色。

预期：界面延续灰度和暖黄色，代码通过低饱和的多种颜色表达语法角色；源码和 diff 两栏保持一致，在增删背景上也有足够对比。

## 原因与修正

误把界面主题的颜色范围直接套到代码高亮，忽略了阅读代码时需要通过颜色快速识别不同角色。调整代码调色板，分别使用紫色关键字、蓝色基础类型与属性、青绿色类型名称、暖黄色函数、橙色字符串与字面量、绿色数字和灰色注释，并在现有词法规则中补充常见属性的识别。

## 防止再犯

- 区分界面强调色和代码语法色，不要求所有代码类别都服从同一种强调色。
- 使用包含类型声明、函数调用、属性、字符串、数字及注释的实际代码核对层次，同时检查增删行背景上的可读性。
- 现有高亮仍是词法规则，不代表完整的 TypeScript 语义分析；不能把按命名和上下文识别的颜色宣称为 LSP 语义高亮。
- 高亮规则不能改变文件内容、行号或 diff 对齐；字符串、注释不应被内部关键字或属性语法重新染色。

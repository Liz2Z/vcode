# 白天主题需要覆盖完整的绘制链路

## 问题与预期

用户要求增加白天主题。原应用在启动时强制 darkAqua，主题和语法色都是面向暗底的常量，部分 hover 直接使用透明白色。仅替换窗口背景会留下低对比文字、暗色材质或不可见的悬停反馈。

## 原因与修正措施

使用 AppKit 动态 NSColor 提供白天／深色语义调色板，单独调整代码语法色，不把 UI 强调色范围套给所有语法角色。CALayer 保存的是已解析的 CGColor，不会自动跟随 NSColor 的动态 provider；设计系统按弱引用保留层颜色来源，在应用外观变化时重新解析背景、边框与阴影。现有 attributed text 只失效显示，不重新读取文件或重建阅读会话。原生输入、材质与标题栏使用同一 AppKit 外观。

View 菜单提供白天、深色、跟随系统三个同级选项，默认白天；选择写入 XDG CONFIG_HOME，损坏配置保留并报告。新配置不影响 XDG STATE_HOME 的历史与布局。

## 检查点

- 同时看源码、diff、Markdown、输入框、选中／hover、行号、提示及菜单，不只检查主底色。
- CALayer 的颜色缓存和 attributed text 的显示失效都必须覆盖，切换不能改变阅读内容或位置。
- 暖黄色在浅色底上使用可读的暖金色文字，代码色在普通及增删背景上均检查对比。
- 构建后固定版本做实窗检查；工具受限操作单独记录，需要用户验证的项目不冒充通过。

本轮自动化和实窗结果待补录。


## 验证结果

新增 5 项主题回归覆盖浅深两种配色下的语法与界面文字对比、CONFIG_HOME 保存与重读、损坏／不可写配置、有效外观变化触发层颜色更新，以及菜单切换时保留正文存储对象、选区、焦点、滚动位置和几何。代码语法色及主要／次要／强调文字在普通和 diff 增删背景上的对比均至少为 4.5。开发阶段首次主题测试只有正文断言失败：CodePane 原有显示会补齐末尾换行，测试把原始输入当作显示值；改为对比切换前已渲染的内容后通过，没有以改动产品内容来规避。最终 51 项相关测试通过，完整 198 项测试全部通过，发行构建及深层签名检查通过。

固定构建实窗观察：首次无主题配置启动直接呈现白天模式；View 菜单有三个同级选项。源码滚动后从 Light 切 Dark 再切 Light，原滚动值 0.9560439560439561 保持一致，已有正文、标签、输入和面板立即换色。暂存／未暂存 diff 的红绿背景、代码颜色及行号清楚；两组编辑器同时展示 diff 和 Markdown，反复切主题后内容和布局不变。Markdown 正文、标题、链接及代码块颜色正确。Quick Open 白色浮层及投影可区分，输入 models 后筛选正常；Search 输入 Project 后命中背景和文件分组可读，Recent 48→200→48 的展开／紧凑配色协调。Follow System 选择被保存为 system；随后切回 light，原生正常退出并确认进程结束后再启动，恢复白天主题和两组阅读内容，配置实际位于隔离的 CONFIG_HOME/vcode/appearance.json，阅读数据仍在 STATE_HOME。

122 项源码、测试、UI 需求及构建文件指纹在实窗检查前后保持一致。分栏 AX 动作一次返回 failure，重新观察确认已成功，未重复点击。工具此前无法稳定捕获类型／Recent 悬停卡片的操作未重复尝试；这两类浮层在新主题下的真实硬件悬停外观标记为需要用户验证。跟随系统的观察链路已通过自动化，实窗只验证系统选项及配置，不擅自切换用户 macOS 全局外观，不声称完成了真实系统设置往返。检查仅覆盖本轮主题相关流程，不冒充全量手动 UI 操作通过。

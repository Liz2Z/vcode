# 忽略普通文件导致相邻目录消失

## 用户纠正与预期

用户指出删除文件修复后，`~/Code/zan-cli` 中实际存在的 `packages/idev-cli/src/auth/` 消失。实地检查确认该目录有源码，是未跟踪目录且未被 Git 忽略；不能将消失归因于空目录、忽略规则或用户没有刷新。

## 已复现的原因

FileBrowser 的磁盘枚举器对忽略名称和符号链接一律调用 `skipDescendants()`。macOS 对普通文件调用此方法会跳过下一个目录的后代。实际目录中 `.DS_Store` 恰在 `auth/` 前，扫描只得到 auth 目录本身，却读不到其中任何文件；文件树由文件路径构建，因此整个目录消失。worktree 的 `.git` 普通文件也会触发相同错误。

修正为只对真实目录调用 `skipDescendants()`。原生枚举器本来不跟随符号链接，不需要对链接额外跳过子项。新增回归先在旧实现下失败，覆盖 `.DS_Store`、`.git` 标记、目录链接及同级目录，确保真实源码保留且不递归链接目标。

## 检查点

- 跳过名称、跳过目录后代是两件事，必须先确认节点确实为目录。
- 不能只验证 Git 跟踪文件；需覆盖新建的未跟踪目录和实际 worktree 的 `.git` 文件。
- 遇到用户给出的真实路径，先做只读扫描对照，确认磁盘、过滤后路径与文件树各阶段的结果。
- 实窗验收前固定构建；验收期间不改产品或测试代码。验证结果如下。

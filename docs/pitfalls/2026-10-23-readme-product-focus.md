# README 应介绍产品能力与调性

## 问题与纠正后的预期

用户要求精简项目 README，核心强调产品能力和调性，不介绍代码；随后明确无需介绍玻璃界面。首页应让使用者快速理解 VCode 的用途、主要能力和获取方式。

## 原因

旧 README 混入界面材质、精确布局参数、实现机制、目录结构、构建流水线及验收记录，产品定位被大量开发细节淹没。此原因已通过旧文档内容核实。

## 修正措施

围绕代码阅读与 Git diff 重写 README，保留核心能力、克制的产品表达、下载入口和少量常用快捷键。去掉玻璃界面介绍及代码架构、构建与测试过程说明，不更改用户维护的 docs/PRD.md。

## 防止再犯的检查点

- 首页先回答为谁解决什么问题、能做什么、如何开始使用。
- 产品调性通过简洁措辞体现，不堆砌视觉材质、控件名称和布局参数。
- 不将计划或未验证的能力写成已支持，不添加未经测量的性能数字。
- 开发、验证和故障记录留在对应文档，不重新累积到产品首页。

本次仅调整文档，未修改产品或测试代码，也未执行 UI 验收。

## 用户再次纠正：调性不是视觉宣传话术

精简后仍保留“交互参考 VS Code，以灰度和暖黄色营造安静、克制的阅读空间”，用户对此提出质疑。问题是将内部交互参考与配色要求写成了对外宣传，并没有提供新的产品信息。现删除这句，保留只读定位；后续用文案本身的简洁与具体体现调性，不再把颜色、参考对象或抽象氛围作为产品卖点。已核对该句移除；未涉及产品功能或 UI 验证。

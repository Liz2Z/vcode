# Recent 常驻栏与宽度模式

## 需求纠正后的预期

用户提供窄条与展开列表的截图，最初文字写“右侧”，随后明确纠正为最左侧，位于文件树外侧。Recent 纵向排列，可拖动右边缘缩放，宽度达到阈值时切换展示方式，最小模式悬停显示完整信息。用户还要求可滚动但不展示滚动条，紧凑模式不在顶部显示删除／清空按钮或保留占位；展开模式保留 Clear All。以这些最新纠正为准，旧的右侧构建、Recent 浮层及顶部开关不再代表当前要求；此前逐条清理能力继续保留。

## 原因与修正措施

旧入口按临时浮层设计，只有打开浮层时才创建内容控制器，点击外部和 Escape 会移除列表，且类型提示把“历史列表存在”当成互斥条件。不能只把浮层挪到右边，否则工作区、清理、焦点和代码类型提示会继续沿用错误的生命周期。

改为常驻控制器，嵌入最左侧独立的原生 NSSplitView，复用已有拖动提示与指针逻辑。历史读写仍交给 WorkspaceHistoryStore，工作区切换仍走既有会话与 Git domain；控制器负责状态更新和交互协调，不在新栏重复实现 Git。宽度低于 160 点时显示简称，达到阈值时显示分组和详情；最窄 48 点、最大 360 点，实际范围同时满足文件栏和各编辑器 220 点的下限。完整路径用于打开与清理，简称只负责展示；使用原生 tooltip 展示完整信息及状态。

宽度属于全局窗口布局，按 XDG STATE_HOME 保存。区分用户选择的宽度与窗口收窄时临时受限的宽度；后台阅读保存不得把临时压缩值写回偏好，否则放大或重启会丢失原布局。Recent 栏宽度保存合并写入，退出时补写最后选择。

## 防止再犯的检查点

- 常驻栏不能参与原来浮层的全局“互斥／关闭”逻辑，也不能因为一直存在而阻断 LSP hover。
- 真正拖动的是面板宽度，不能用加宽间距或命中区域代替缩放；两侧与编辑器分栏使用一致的边界。
- 覆盖阈值两侧往返、最小宽度、长名称、相同简称、同名项目、多个 worktree、不可用记录，以及清理时不误切项目。
- 切换与刷新后更新当前标记、分支及可用状态，失败不切换旧会话；清理不删除磁盘内容。
- 验证默认窄栏、展开、双编辑器与窗口压缩、重启恢复；工具无法捕获的真实悬停／指针／物理拖动标记为需要用户验证，不重复尝试。
- 开发回归曾出现测试窗口实际内容为零尺寸的情况；按新布局检查前必须设置实际内容尺寸，不能把旧浮层独立尺寸的断言沿用到嵌入栏。此项通过测试几何核实，不作为真实应用零尺寸问题的证据。

## 紧凑栏的视觉纠正

用户确认原生悬停提示能够显示完整信息，但明确反馈“太丑了”；这是用户验证的功能可用、视觉不通过，不能继续记成只是工具无法捕获。用户进一步要求紧凑状态不显示任何删除按钮，整条竖栏不要底色。先前只去掉顶部 Clear All、保留每条记录的 ×，理解范围不足；灰色长条底板及当前项实心底色也让简略导航显得拥挤。

按新的明确纠正，停止先前左侧构建验收：紧凑栏、列表与当前项透明，只有暖黄色当前名称和临时 hover 反馈；顶部和每行的删除／清空按钮全部隐藏，展开后才出现。详情改为独立的应用内灰色卡片，以名称、分支、换行路径和状态分层，不重复展示相同的项目名，不再叠加系统 tooltip。卡片不抢键盘焦点，移入继续显示，移出两秒后关闭；滚动、切换模式／记录、窗口变动与退出会清理旧卡片。

检查点：不能只检查按钮 action 正常，也要自己看完整密度、留白和底色；按用户说的“紧凑状态”检查所有操作，不能只处理顶部。系统原生控件优先不等于系统 tooltip 的视觉总适合此场景；既有 Git 选择器不属于此次改造。新版固定构建与实窗结果待补录，旧版拖动／清理通过不能替代新版外观验证。

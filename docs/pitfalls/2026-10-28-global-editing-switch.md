# 普通文件编辑权限必须全局控制且默认只读

## 问题与纠正后的预期

用户要求普通文件的编辑能力提供开关，并明确选择全局控制所有普通文件，不能按单文件或分栏各自开关。编辑权限默认关闭，每次重启恢复关闭；当前文档是否可编辑仍独立显示，避免开启后将 diff 标成可编辑。

用户在独立预览中确认开关行为、保存和指针正常，但进一步指出底部独立按钮太突兀。因此先撤去状态栏新增控件并放入 Edit 菜单。用户进一步明确提出直接点击 Read Only／Editable：最终沿用既有锁／笔图标与状态文字，将它们作为无常驻边框／底色的原生按钮，不另加标签和开关。Edit → Allow File Editing 保留为同步入口。功能验证通过不等于视觉方案获认可，不将低频全局配置持续摆在阅读区旁。

## 原因

既有实现将普通文本的可编辑能力和当前编辑权限合并，打开文件及解除切换暂停时会直接启用 NSTextView 编辑。保存菜单也依赖同一标志；简单关闭编辑会连带禁用已有改动的保存。以上已核实于 EditorView 与 WorkspaceController。视觉问题来自新增的常驻标签和开关打断原有紧凑状态栏层级；这是基于用户反馈和实窗对照的设计判断，不归因于系统控件故障。

## 修正措施

普通文件通过底部模式按钮直接切换，草稿／diff 或无可用普通源码时不提供误导性解锁。行列、计数及错误消息与模式文字分开，避免光标移动把入口覆盖。在 Edit 菜单通过校验同步勾选状态，并在确认浮层期间锁定动作；移除底部 NSSwitch 和附加标签。将会话级权限传给所有已有和新建编辑器，统一根据文档类型、源码缓冲、错误状态及临时暂停计算是否可编辑。保存资格与继续输入权限分离，关闭后保留改动并允许保存。草稿不受普通文件总开关影响，diff 不受开关解锁。权限只存在内存，不增加 UserDefaults 或 XDG 配置写入。跨项目保留本次运行选择，重启的新控制器默认关闭。

## 防止再犯

- 覆盖默认关闭、双栏和新增文件、项目切换、恢复和刷新，以及草稿／diff 权限隔离。
- 关闭再开启保留选区、查询、阅读位置与撤销记录；关闭后已有改动可保存，干净只读文档不可保存。
- 临时暂停解除和错误提示不能反向开启编辑。
- 实窗检查原生菜单勾选、底部仅原模式文字和图标可点击且无额外常驻背景、文档实际状态及浅深色，不将自动化中的控件状态冒充用户操作结果。

验证结果另记于 docs/verification/2026-10-28-global-editing-switch.md；尚未完成的实窗项不能视为通过。

## 状态文字指针再次被用户指出错误

用户反馈新版 Read Only／Editable 的 pointer 不对，记录为用户验证失败，而非继续沿用“需要验证”状态。用户的反馈明确要求修正此交互；本轮修复依据该反馈，不从此前 UI 验收自行推导修复授权。

已核实代码仅复用了 PointingHandButton 的 resetCursorRects，没有将已存在于文件树、Recent 和查询框的首次进入／移动／cursorUpdate 协调沿用到状态栏。具体 macOS 原生事件覆盖时序尚未核实，不宣称已确认底层系统根因。此前仅凭复用按钮基类推定首次悬停也完整继承，遗漏了已有踩坑检查。

修正预期：普通文件模式文字、锁／笔图标和按钮留白首次移入即手形，不用先点击；Read Only↔Editable、宽度变化和窗口缩放后继续正确；草稿、diff、错误及无文档的不可点击模式、状态栏静态文字与留白使用箭头。移出状态栏不强制覆盖正文的文本指针。沿用合法的两类跟踪区域，activeAlways 的进入／移动与 activeInKeyWindow 的 cursorUpdate 分开；状态切换和布局时重建命中区域，后台布局不抢前台指针。

防止再犯：复用 cursor rectangles 只能证明注册存在，必须另测首次进入、移动、cursorUpdate 和静止鼠标下状态变化。自动化事件断言与真实屏幕指针分别记录；用户反馈失败不能被局部测试通过覆盖。新版修复的实际结果待补录。

指针修复回归补录：新增首次事件用例在旧版复现 162 处断言失败；修复后 25 项权限／指针／查询回归与新增的静止指针单项通过，共 26 个不同用例。静止指针用例覆盖标题变短后的旧区域退让、可用性变化、后台不争抢及状态栏外不覆盖。真实首悬停仍待新版用户确认，不把模拟事件与窗口属性断言当作系统完整事件流验证。

## 悬停反馈与玻璃虹彩

用户先补充鼠标移入时用背景提示可交互，随后要求炫一些的玻璃色散效果。最终预期是原模式入口仅在悬停时浮现玻璃和细虹彩边缘，移出即消失，默认透明；不能重新做成常驻独立大开关。采用共享 GlassSurface，macOS 26 使用 NSGlassEffectView 的 clear 样式，旧系统原生材质回退；26.2 SDK 未提供独立色散参数或交互光学参数，因此虹彩边缘用 Core Animation 细渐变轮廓补充，不宣称系统原生自带可控彩虹色散。鼠标移动只更新轮廓高光位置，不做常驻动画。

装饰层必须完全透传命中，按钮仍是唯一点击入口；首次进入、移动、禁用及静止鼠标下状态变化同时更新手形与玻璃显示，离开时只清理视觉，不覆盖下一视图指针。复用原生玻璃时仍需实窗检查可见效果，不能凭材质类名或渐变层存在宣称外观通过。最终构建和实窗结果待补录。

## 虹彩悬停版交互通过，视觉被用户否定

用户确认“功能正常。效果有点丑。”：将新版首次手形、玻璃显隐等交互记录为用户验证通过，外观仍未通过，不再重复索取同一功能确认。用户没有指出具体丑在哪里；代码中额外彩色渐变轮廓、鼠标跟随高光及胶囊轮廓已核实存在，它们增加小状态入口的装饰感属于设计判断，不能冒充用户给出的具体原因。

本轮根据该视觉反馈修正：删除虹彩渐变、装饰描边和鼠标跟随高光，只复用共享 GlassSurface 默认的中性原生玻璃；圆角沿用 Theme.Layout.controlRadius，降低阴影强度。保留用户已确认的交互、装饰命中透传及仅悬停显示，不重新加入常驻开关。检查点：小状态入口先保证与周围状态栏协调；原生材质无需再叠加模拟色散来证明“玻璃感”，视觉认可与功能通过必须分开记录。新版实际外观尚待验证。

## 用户最终指定普通背景、小圆角及左右留白

用户进一步明确“改成普通背景色”，并指出背景紧贴文本、圆角过大。当前以此为最终视觉要求，不继续尝试玻璃、色散或胶囊形态。已核实之前的玻璃装饰与原生按钮同宽，而原生按钮没有额外横向内容留白；圆角曾采用 12／8 点，因而不符合本次小圆角要求。

删除状态栏专用玻璃组件，改用 Theme.hover 普通灰度底，4 点圆角，不附加阴影／模糊。模式按钮在原生固有宽度基础上增加 16 点，文字与图标组居中，使左右各有 8 点额外留白；按钮与背景共享完整边界，留白同样响应点击及手形。保留已由用户确认的权限与指针事件流程，不重新要求用户验证同一功能。检查点：不要仅给文本固有宽度上色；所有带背景的文字入口必须同时考虑内容边距、圆角与真实点击范围。新外观仍待最终实窗检查。

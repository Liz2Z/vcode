# 标签能排序不代表拖动体验合格

## 用户反馈与预期

用户要求文件标签支持关闭所有、关闭其他、关闭左右及拖拽排序。首版使用 NSDraggingSession：拖动图像跟随鼠标，插入线指示位置，放下后更新顺序。用户手动确认可以排序，随后明确指出交互不够顺滑。

排序能力记录为用户验证通过；交互体验不能因此一并记为通过。待确认的改造方向是标签本体跟手移动，相邻标签实时平滑让位，松手贴合位置，Escape 恢复原顺序。保留批量关闭、当前文件与源码／暂存／未暂存身份。

## 原因与检查点

已确认首版只有放下时才重排标签，其余标签没有实时让位动画。该机制与文件拖放相同，能够完成排序，但缺少用户期望的连续反馈；具体动画与跟手效果尚未实现。

- 对标签排序分别验收能力和体验，不能以 NSDraggingSession 已接入或排序结果正确代替交互验收。
- 工具未结束原生拖放时，不反复尝试同一受限操作；用户已确认排序可用，明确区分工具操作结果与用户验证。
- 四项关闭菜单在固定构建实窗通过，同一路径的三个比较标签可独立保留，关闭全部的空状态正常。
- 当前为 UI 验收反馈阶段，只记录问题，等待用户明确确认改造后再修改产品与测试代码。

## 当前处理决定

用户询问难度，并表示“复杂就算了”。实时跟手让位需要更换现有拖放机制，还要处理边缘滚动、取消恢复及布局动画，属于有一定复杂度的交互改造。按用户控制复杂度的偏好，本轮暂缓此改造，保留已确认可用的排序和四项关闭菜单。

排序能力的用户验证仍有效；顺滑体验反馈保留为已知限制，不改写成体验已通过，也不继续等待本轮改造授权。此阶段仅更新处理决定，未修改产品或测试代码。

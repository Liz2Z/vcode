# 搜索与引用高亮必须使用独立语义颜色和概览列

## 问题与纠正后的预期

用户截图指出搜索高亮与标识符点击高亮混在一起。确认方案后，进一步明确搜索在 minimap 中也应独立一列。引用保留用户指定的亮黄色，搜索改青蓝色；当前搜索结果加强底色并加细边框，文本真实选区优先沿用系统样式。

## 原因

已核实：CodeLayoutManager 原来给搜索和引用均使用 Theme.accent，只改变透明度；两者背景顺序叠加。CodePane 把引用与搜索行合并传给同一个 occurrenceRows，概览无法区分这两种语义。选区也使用暖色 accent，使搜索导航产生的程序选区与点击反馈进一步混淆。

## 修正措施

搜索与引用使用独立颜色，正文按系统文本选区、搜索、引用的优先级绘制，排除重叠背景。程序搜索导航保留真实选区用于复制和下一次定位，但交由查询 renderer 显示当前命中；用户重新选区后恢复系统选区。概览左侧青蓝搜索列、中央黄色引用列、右侧相邻 Git 红绿列，各固定 4 点。Original 的搜索及当前命中通过独立字段同步到共享概览，不能再混入黄色引用列。

## 防止再犯的检查点

- 浅深主题分别检查搜索、引用、当前命中与用户选区，不能只检查单个效果。
- 搜索与引用同词、部分相交、同一行不同词均不混色；当前命中不被原生程序选区盖成另一色。
- 当前结果移动时正文边框和青蓝概览强调同步；编辑、清空、关闭和切文件清理查询状态，保留引用。
- 用户拖选即使范围等于当前搜索结果，仍恢复系统选区；查询导航不会改变源码可编辑性。
- 概览独立列必须同时检查普通源码、Original／Modified、Git 同行及不同轨道宽度，标记维持固定宽度。

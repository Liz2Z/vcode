# 删除记录需要名称层面的视觉区分

## 问题与预期

用户提供 VS Code 参考图，要求优化已删除文件的展示。原界面仅用右侧红色 D 标记，文件名与普通记录相同；本次明确为 Changes 中的删除名称增加单条删除线和次要文字色。目录、分组、状态和操作按钮不加删除线，删除行仍可阅读旧内容及进行索引操作。

## 原因与措施

已核实：FileTree 原来只按 Git 状态给 badge 着色，没有名称删除样式。采用 AppKit 原生 attributedStringValue 绘制单条删除线，保留字号、字重、中间省略及动态颜色；每次配置单元格都完整赋值，避免删除样式随复用泄漏。

## 防止再犯

- 以当前比较分类的删除状态为准；已暂存删除后同路径重新创建，Files 与未暂存的新文件不能被划掉。
- 刷新由删除变为修改、复用为目录或分组时恢复正常样式。
- 保持 D 标记与 hover 操作可见，删除线不能跨越整行。
- 此次自动化与浅深主题实窗待验证，完成后另记录结果；不把之前暂存功能的用户验收当成此项通过。

## 本次结果

FileTreeTests 与 IndexActionTests 共 18 项通过，发行构建通过。独立预览在解锁后完成浅深主题、长名称中间省略、普通及选中删除行、已暂存／未暂存删除 diff 的实窗检查。专用示例同路径重建时，已暂存删除保留删除线，未暂存新文件正常；加入索引变为 M 后自动刷新并移除删除线。冻结清单无变化，验收中没有修改产品或测试代码。详情与证据记录在 docs/verification/2026-10-26-deleted-change-style.md。

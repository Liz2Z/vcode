# 需求

1. **平台与技术**：

   1. macOS；采用原生方案或 Tauri，不使用 Electron。

   2. 能力实现：能用三方包就用三方包。

2. **交互体验**：

   1. 操作直观：操作区域能直接展示就直接展示，不要隐藏在下拉菜单或二级菜单。

      1. 文件夹列表这种涉及大量 IO 的默认折叠，必要时才加载，优化性能；
      2. LSP 类型定义和跳转还是按照 vscode 的交互。这种不可能放个按钮，你动动脑子

   2. 反馈清晰：按钮的hover、active 等都要有明显反馈。

   3. 可点击区域的鼠标指针：按钮、标签和可点击行用手型，代码区保留文本光标，分隔条保留左右调整指针

3. **能力：**

   1. **全部文件浏览**：通过树状目录查看项目中的所有代码，点击文件阅读完整源码。

      1. 支持 typescript 的语法高亮和 markdown 的预览；
      2. 支持 typescript  项目的 LSP；
      3. 点击文件夹那一项任何地方都能切换展开/折叠，而不是必须点击图标
      4. 文件树的每一项也需要支持 hover、active 的状态区分

   2. **改动查看**：改动文件列表也采用树状结构；点击后显示左右双栏 diff，便于对照修改前后的内容。

      1. diff  tree 要默认全部展开；
      2. 支持展示已暂存/未暂存两个分类；
      3. 被改动的文件，目录树的每个文件项的右侧要展示其改动类型和颜色表示；
      4. 有改动时，且不在 changes tab. 时，changs tab 要有个点提醒下，发光的那种感觉。
      5. 在滚动条处支持下 git diff mini map

   3. **语言能力**：首版支持 TypeScript 语法高亮和 LSP；后续考虑增加 Python。

      1. hover 在 identifer 处展示具体类型，也有要有高亮提示和格式化，参考 vscode，注意窗口边界；
      2. 代码调整需要支持多层级的跳转，不能只支持顶级定义跳转；
      3. 一个类型定义，也要能展示它的被引用的列表；
         1. 就是一个identifer 本身就是定义了，那 command + 左键点击，应该直接展示它的引用列表。
      4. hover  移除后，弹框要过2s 才消失，触发触发了别的弹框。且如果鼠标移动到弹框上之后，弹框不能消失，这样支持用户继续看弹框内容的详情。
      5. identifier 的高亮
         1. 默认情况下hover 不处理；
         2. command +鼠标hover  一个标志符的时候，如果它可以跳转，则展示下划线；
         3. 点击一个 标志符时，背景色高亮它以及当前文件内它的引用和定义；
         4. 跳转到目标定义时，目标定义需要背景色高亮/取消，闪烁 2s 提示；

   4. **支持切换worktree 和分支**

   5. **编辑器**

      1. 文本渲染
         1. 字体：Monaco, Menlo; 字号：12
         2. 字体垂直居中；
         3. 行高
      2. 打开的编辑器
         1. 支持右键菜单：
            1. 关闭所有
            2. 关闭其他
            3. 关闭右侧
            4. 关闭左侧
         2. 拖拽调整顺序
         3. tab 太多时能够左右滚动
            1. 同时支持拖拽滚动条滚动
         4. **阅读位置前进／后退**：跳转定义、切文件后，可以回到原来的文件、光标和滚动位置。分栏后尤其需要。
            1. 基于 **LSP 找定义 + TextKit 定位显示 + 内容锚点恢复历史**。
           
         5. 双击标签栏空白处，或按 ⌘N，新建可编辑标签。
           6. 支持撤销／重做、⌘S 保存、⌘⇧S 另存。
           7. 未保存草稿随会话恢复，项目源码和 diff 保持只读。

   6. **会话持久化**

      1. 支持展示打开过的：项目-worktree列表，方便快速切换
      2. 重开应用后恢复项目、分栏、标签顺序和阅读位置、文件树打开状态，按 worktree 隔离

   7. 文件树

      1. 不要使用图标来标记不同的文件类型
      2. **文件变化自动同步**：外部修改、删除、重命名或切换分支后，文件树、源码和 diff 自动更新，并尽量保持当前阅读位置。
      3. .gitignore 命中且未被 Git 跟踪的文件也要在 files 中展示，⌘P 文件匹配和全局搜索仍排除它们。

   8. 模块缩放

      1. 左侧边的拖动，我希望鼠标移动到可拖拽区域时，展示一根提示条；
      2. 可拖拽的移动范围，侧栏最窄 220 点，最宽时右侧保留 220 点；
      3. 始终用双向的左右调整指针。拖到最左、最右边界时，也不切换成单向箭头；

   9. 资源监控

      1. 在**macOS 菜单栏**：**VCode → Resource Usage…**，就在 **About VCode** 下方。看到这个应用的资源占用情况

   10. 全局查找

       1. **快速打开文件**：⌘P 模糊搜索文件名和路径，优先显示最近打开的文件。大项目里比逐层展开目录快很多。
       2. **项目全文搜索**：支持大小写、整词、正则和目录排除；结果按文件分组，点击定位到具体行。

   11. 快捷键：

       1. ⌘P 全局模糊搜索文件名和路径
       2. ⌘+shift+f 项目全文搜索
       3. ⌘R 刷新数据
       4. 快捷键列表浮层，用 **⌘K ⌘S** 呼出，可以查阅所有快捷键。
       
   12. 文件类型关联与系统打开集成
       1. VCode 向 macOS 注册常见开发文件类型，支持从 Finder 的“打开方式”、拖拽文件到应用图标等入口打开并阅读文件；不主动抢占默认打开方式。
       2. 打开的文件必须处于一个git 仓库内。


    13. 打开的项目
        1. 在左侧，纵向排列，可拖拽缩放，到阈值后切换展示方式，两种模式：紧凑模式和完整模式；
        2. 紧凑模式下，鼠标悬浮展示详细信息。
        3. 详细模式下按照 git 分类展示各个worktree
   
    14. 支持黑白主题
        1. 白色主题的主题色要黄偏红一点
  
    16. 支持自动更新

  
5. 视觉：

   1. 整体看上去配色自然，灰度为主，搭配姜黄色；

   2. 模块化，使用不同灰度区分，禁止过多的线条分隔；

   3. 内外圆角要和谐、padding、margin 范围自然；

   4. 对比足够；

   5. 渲染清晰；

6. 代码设计：

   1. 使用 DDD 模式设计代码，比如：worktree 和 文件变更 都属于 Git. 能力，只是展示位置不一样，你需要抽象的==是一个git domain, 在 ui 上分别使用它不同的能力。

7. 持久化数据

   1. 按照 XDG 规范存储数据
